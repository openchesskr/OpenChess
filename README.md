# OpenChess

체스 오프닝 학습·연습 애플리케이션.

## 개발 워크플로우 규칙 (모든 세션 필독)

- **PR을 임의로 생성·머지하지 말 것.** 어떤 이유로든(작업이 끝났다고 판단되더라도, 이전에 "PR 만들자"는 지시가 있었더라도) 새로 PR을 열거나 머지하기 전에는 반드시 사용자에게 먼저 물어보고 명시적 승인을 받는다. 문서 수정·버전 라벨 정정처럼 사소해 보이는 변경도 예외 없음 — 커밋/푸시까지만 하고 PR 생성 여부는 승인 후 결정한다.
- **PR 번호를 버전 번호에 맞춘다.** 이 프로젝트는 PR 번호와 배포 버전 번호를 의도적으로 맞춰 나간다. 예: v0.1.0(비교적 큰 단위 업데이트)은 PR #10에 맞출 예정. 새 PR을 만들기 전 다음 PR 번호가 계획한 버전과 맞는지 확인하고, 안 맞으면 사용자에게 확인받는다.
- **"버전 기록"은 PR 생성 전에 자동으로 채워 넣는다.** 아래 "개발자 기록"(채팅 전용, 머지 후 1회)과는 별개로, README `## 버전 기록` 섹션과 `src/App.jsx`의 CHANGELOG 배열(접속 시 뜨는 공지 모달의 내용이자 APP_VERSION이 파생되는 곳), 그리고 `src/AboutPage.jsx`의 `VERSION_HISTORY` 배열(`/about` 소개 페이지의 버전 기록 탭)까지 **세 곳 모두** 매 세션·매 버전마다 PR을 만들기 전에 그 버전 커밋에 포함해 둔다 — 사용자에게 물어보지 않고 항상 진행하며, 세 곳 중 하나라도 빠뜨린 채 넘어가지 않는다(과거 v0.1.2·v0.1.3이 `VERSION_HISTORY`에서만 누락된 채 배포된 적이 있었음 — 재발 방지). README 버전 기록은 기존 항목들과 같은 형식(`### OpenChess vX.Y.Z — 날짜` 헤더 + 보안/성능/기능/버그 수정/UI/UX/시스템 등 실제 해당하는 카테고리만 굵게, 개발자 관점의 상세 서술)으로 적고, CHANGELOG 배열에는 그 내용을 개발 용어 없이 사용자 입장에서 쉬운 말로 다시 정리해 새 항목을 배열 맨 앞에 추가한다. `AboutPage.jsx`의 `VERSION_HISTORY`에는 같은 내용을 CHANGELOG와 같은 쉬운 말로, 다만 카테고리(`feature`/`ui`/`ux`/`perf`/`fix`/`security`)로 나누고 `summary` 한 줄 요약·마스코트 도입부/마무리 멘트(`mascot.intro`/`outro`)·대표 기능 하이라이트(`highlight`)까지 갖춰 배열 맨 앞에 추가한다(버전 번호는 세 곳이 항상 일치해야 함).
- **매 버전(모든 세션)마다 "개발자 기록"을 남긴다.** 이건 사용자가 머지 후에 체크해야 할 할 일(TODO) 목록이 아니라, 그 버전에서 실제로 무엇을 개발했고 무엇이 어떻게 적용됐는지에 대한 기술적 기록이다 — 원인 분석, 선택한 해결 방식, 실제로 바뀐 동작 위주로 서술한다. PR 본문이나 README 버전 기록에 적지 않고, 채팅으로 사용자에게 텍스트로 직접 작성해 보여준다. 문장은 사용자가 개발 중 쓰는 말투를 살려 "~할 것" 형식의 간결한 항목체로 적는다.
  - **시점**: 세션 중 커밋할 때마다 바로바로 남기지 않는다. PR을 생성하고 사용자가 머지한 뒤, 그 PR(버전)에 실제로 들어간 변경사항 전체를 한 번에 모아 요약해서 남긴다 — 같은 세션에서 여러 번 커밋했어도 기록은 머지 후 한 번만.
  - **형식**: 날짜 → "개발 방향 : ..." 한 줄 요약 → 카테고리별(보안/성능/기능/UI/UX/시스템/의존성 등 실제 해당하는 것만) 번호 매긴 목록. 예시:
    ```
    2026/7/14

    개발 방향 : 보안 강화 및 성능 개선

    보안
    1. puzzles 테이블 RLS를 손볼 것 — update가 using(true) with check(true)로 전체 개방돼 있어 로그인 없이도 임의 퍼즐의 solves/likes 카운터를 직접 덮어쓸 수 있었음. 컬럼 단위 grant로 좁혀 두 카운터는 puzzle_solve/puzzle_like_toggle RPC로만 바뀌게 할 것.
    2. notifications insert 정책을 강화할 것 — auth.uid() is not null만 검사해 로그인만 하면 아무 유저에게나 아무 종류의 알림을 위조해 보낼 수 있었음. kind별로 실제 발생 가능한 상황인지 서버에서 검증할 것.

    성능
    1. 알림·친구요청 배지·채팅창·안읽은 채팅 배지 폴링을 Supabase Realtime 구독으로 전환할 것 — 소켓이 조용히 끊기는 경우를 대비해 느슨한 안전망 폴링만 남길 것.
    ```

## 버전 기록

### OpenChess v0.2.6 — 2026/7/28

**버그 수정 — 탁월한 수(brilliant) 판정 추가 보정**
사용자가 제공한 3개 실제 대국을 기준으로 `isSacrifice` 계열 판정을 추가로 다듬었다. (1) 24.Re1처럼 룩을 상대 대형 뒤 배후로 들여보내 메이트 그물을 짜는 패턴이 탁월로 잡히지 않던 원인을 분석해, 새 `hasSaferSquare` 헬퍼로 "지금 방치된 것처럼 보이는 기물이 사실은 더 안전한 칸으로 피할 수 있어 위협이 허상인" 경우를 가려내 같은 패턴의 수들도 탁월로 인정되게 했다. (2) 13...Qxc3처럼 잡히는 기물(비숍)이 사실은 안전한 경우 — 그 기물을 잡으면 룩이 퀸을 스큐어로 노리게 되는 등 — 을 탁월로 오판하지 않도록, 기물을 잡은 뒤 정말로 다음 수에 즉시 그 점수를 돌려받지 못하는지까지 확인하는 검증을 강화했다. (3) 16...Nf3+처럼 먼저 기물을 희생한 뒤 그 대가로 점수를 회복해 가는 콤비네이션 수순에서, 첫 희생 수 이후 연달아 나오는 "점수 회복용" 후속 수들까지 탁월로 중복 표시되지 않도록 새 `ownPriorMoveWasSacrifice` 헬퍼로 직전 자신의 수가 이미 희생 수였는지를 추적해 `classifyMoveKind`·`analyzeGame`과 3곳의 인라인 중복 판정 블록 전부에 가드를 추가했다.

**버그 수정 — 집중 학습 미니보드 캐슬링 애니메이션**
`AnimatedMove`가 캐슬링 수를 재생할 때 `sanSrc()`가 킹의 좌표만 반환해 킹만 슬라이드하고 룩은 제자리에 얼어붙어 있던 문제를 고쳤다. 캐슬링 여부(`geo.castle`)에 따라 룩의 시작/도착 좌표(`rookFr`/`rookTo`)를 함께 계산해 킹과 룩이 동시에 각자의 목적지로 슬라이드하도록 했다.

**버그 수정 — 엔진 라인 타이핑 미완료·자동 스크롤 방향**
`TypedMoveLine`이 라인마다 `setTimeout`을 의존성 배열과 함께 재귀 호출하는 방식이라 리렌더 타이밍에 따라 중간에 멈춰버리는 경우가 있었다 — 포지션 키(`posKey`)당 단일 `setInterval`로 재작성해 타이핑이 끝까지 안정적으로 진행되게 했다. 또한 `EngineLineRow`가 라인이 길어질 때마다 스크롤을 마지막 수(오른쪽 끝)로 자동으로 밀어붙이던 `followTail`/`followRef` 로직을 완전히 제거해, 다음 수가 항상 왼쪽에 붙어 보이도록 정리했다.

**버그 수정 — 엔진 라인이 여전히 중간에 끊기던 진짜 원인(useEngine 큐 경합)**
위 수정 이후에도 사용자가 빠르게 수를 두거나 포지션을 넘기면 특정 줄의 수순이 특정 지점에서 영구히 멈춰 보이는 현상이 재발했다. `chromium`을 헤드리스로 띄워 실제 재현해 보니, 멈춘 줄의 표시 텍스트가 지금 포지션과 무관한 수순(예: 1.e4 e5로 이미 넘어갔는데 1...c5로 시작하는 PV)이었다 — `chess.js`로 합법성을 검사해 보니 실제로 이전 포지션의 PV 데이터가 새 포지션의 MultiPV 결과에 섞여 들어가 있었다(`pvUciToSans`가 색이 어긋난 UCI 수를 만나 SAN 변환에 실패하고 그 지점에서 조용히 멈춘 것). 근본 원인은 `useEngine`의 `supersede`(같은 slot의 새 요청이 오면 실행 중이던 이전 요청을 "stop"으로 중단시키는 함수)가 엔진의 실제 `bestmove` 응답을 기다리지 않고 곧장 큐에서 그 작업을 빼고 `running`을 `false`로 되돌려, 바로 이어지는 다음 요청의 `position`/`go`를 같은 엔진 워커에 즉시 보냈다는 점이었다 — 그 사이 도착하는 이전 탐색의 뒤늦은 `info` 줄들이 `handleLine`에서 "지금 큐 맨 앞"(=이미 새로 들어온 다음 요청)의 결과 버퍼로 잘못 합쳐졌다. `supersede`가 중단시킨 작업을 곧장 빼지 않고 그대로 큐에 남겨 두어, 실제 `bestmove`가 도착해 자연스럽게 큐가 흘러갈 때까지는 다음 요청을 엔진에 보내지 않도록 고쳤다 — 그동안 들어오는 뒤늦은 `info` 줄은 이미 `settle`된 자리로만 흘러가(그 자리의 콜백은 자신의 포지션 키 검사에서 걸러져 무시됨) 다음 요청의 결과와 섞이지 않는다. 헤드리스 브라우저로 초를 다투는 빠르기로 수십 수를 연달아 두며 재현·검증했다.

**UX — 드래그 스크롤 감도 상향**
도감(오프닝 모식도), 현재 대국 기보, 엔진 라인에서 포인터 드래그로 가로 스크롤할 때 체감 이동량이 실제 손 이동량보다 작게 느껴지던 것을, 공용 상수 `DRAG_SCROLL_MULT = 2.2`를 도입해 `EngineLineRow`·`SequenceBar`·`OpeningSchematic` 세 곳 모두에 동일하게 적용했다.

**UI — 프로필 카드·집중 학습 폰트·레이아웃 통일**
"자주 두는 수" 정보에 Playfair Display 폰트를 적용했다(`TopOpeningsAnimated`, 기존 `TopWhiteMovesAnimated`에서 이름도 변경). `MyProfileCard`의 OpenChess 자체 정보와 chess.com 통계 사이에 점선 구분선과 "Chess.com 통계" 아이콘+텍스트 헤더를 새로 넣었다. 집중 학습(`FocusPanel`)의 chess.com 통계 카드 중 최근 대국 목록 UI를 프로필 카드와 동일한 스타일로 통일하고, 집중 학습에서 보여주는 모든 수 표기에도 Playfair Display를 적용했다.

**기능 — 프로필 오프닝·전적 표기 개선**
가장 많이 둔 오프닝을 수순 표기(예: "1.e4 e5") 대신 오프닝 이름으로 보여주고, 그 아래에 흑 레퍼토리 기준 오프닝도 함께 보여주도록 `TopOpeningsAnimated`를 확장했다. 승/패/무 표기를 승리/패배/무승부로 풀어 쓰고, 레이팅 변동을 결과에 바로 붙여 "승리(+9)"처럼 한 줄로 보여준다. 오프닝 이름이 바뀔 때마다 카드 폭이 흔들리던 문제를 폭 고정으로 해결했고, 대국 날짜는 시간 규정 옆 괄호 안으로 옮겼다. "그 외 변형" 라벨은 "Side Line"으로 이름을 바꿨다.

**버그 수정 — 모바일 말풍선·카드 화면 잘림**
수 아이콘 설명 팝오버가 화면 가장자리 근처 수에서는 화면 밖으로 잘려 나가던 문제를, 화면 중앙까지의 거리를 기준으로 안전한 방향을 판정하는 공용 함수 `safeAreaDx`를 새로 만들어 해결했다(`CircleBadge`). 기존의 작은 툴팁 방식 코드는 완전히 제거하고, 같은 원리를 채팅 롱프레스 삭제 메뉴와 알림 카드(`NotificationBell`)에도 동일하게 적용했다.

**기능 — 퍼즐 화면 대규모 개편**
해결한 퍼즐도 오프닝 테마별 점선 상자로 묶어 보여주도록 `PuzzleTab`의 그룹핑을 `groupByTopOpening` 재사용으로 통일했다. 별(`LineStars`) 크기·간격을 줄이고, 좋아요·재게시·공유 순서로 소셜 아이콘을 재배치하며 크기를 키웠다. "라인 a/b 해결" 표기를 "a/b"로 축약했다. 코치 말풍선은 대기 상태에서 새 `summarizePosition` 함수로 현재 포지션을 요약해 보여준다. PGN은 별도의 스크롤 가능한 한 줄짜리 박스(`PuzzlePgnBox`)로 분리했고, 보드 아래 텍스트 프롬프트 자리는 평가치 바(`EvalBar`)로 대체했다. 퍼즐 모식도(`PuzzleSchematic`)에서 "라인 n" 라벨과 체크마크를 마지막 수 블록 오른쪽으로 옮겼다. `genPuzzleTree`/`puzzleCandidatesAt`의 평가 depth/movetime을 게임 리뷰와 동일한 `REVIEW_DEPTH`/`REVIEW_MOVETIME_MS`로 맞춰 라인 생성 시점과 재평가 시점의 평가치가 어긋나던 문제를 해결했다. 힌트 체계를 3단계 시각 힌트(칸 반짝임 → 기물 흔들림 → 이동 경로 애니메이션)로 완전히 새로 짰다 — 나이트는 고정된 L자 분해로 경로를 표시하는 `hintPathSquares` 헬퍼를 새로 만들고, `Board` 컴포넌트에 `hintTo`/`hintFrom`/`hintPathSq` prop을 추가했으며, 새 CSS 키프레임(`hintSquarePulse`/`hintSquarePop`)을 도입하고 힌트 버튼 UI도 단계에 맞춰 갱신했다.

**기능 — 채팅 기능 확장**
연속으로 온 상대 메시지 묶음의 첫 번째 말풍선 왼쪽에 상대 프로필 사진을 보여주고(클릭 시 프로필로 이동), 메시지 안의 "@사용자명" 멘션은 굵게 강조되며 클릭하면 해당 프로필로 바로 이동한다(`MENTION_RX`·`renderMentionText`·`ChatUserProfileModal`). 입력 중 표시 말풍선은 기존 3점 바운스 애니메이션을 유지한 채 투명도 50%로 낮췄다. 입력창이 "/"로 시작하면 슬래시 명령어 자동완성 블록이 뜨는데, 이번 버전엔 `/puzzle -num 000000` 또는 `/puzzle 000000` 형식으로 해당 번호의 퍼즐을 공유하는 명령어 하나만 담았다.

**기능 — chess.com 통계 흑/백 분리 및 레이팅 변동 그래프**
시간 규정(전체/래피드/블리츠/불릿) 필터에 더해 흑/백 색 필터를 추가했다 — 시간 규정 선택 박스를 조금 줄이고 같은 줄 오른쪽에 색 필터를 나란히 배치했다. "전체 기간 전적"과 "최근 대국" 사이에 지금 걸린 필터가 적용된 대국들을 시간순으로 이은 기간별 레이팅 변동 선 그래프(`RatingHistoryChart`, 첫 레이팅→마지막 레이팅과 최저/최고를 함께 표시)를 새로 추가했다.

**UI — "자주 두는 첫 수" 레이아웃 개편, 통계 헤더 문구 단순화, 레이팅 그래프 보강**
사용자가 그린 스케치를 따라 프로필의 "자주 두는 첫 수"(`FirstMovesDisplay`)를 세로 목록에서 "백"·"흑" 두 박스를 나란히 두는 레이아웃으로 바꿨다 — 왼쪽 박스엔 자주 두는 첫 수(백)를 큰 글씨로, 오른쪽 박스엔 백의 각 첫 수(`e4`/`d4`/`c4`/`Nf3`, 프로필 편집기 입력 순서 그대로)에 대한 흑의 응수를 "1.e4 e5" 형태의 한 줄씩으로 묶어 보여준다. 프로필 카드의 "Chess.com 통계" 헤더 문구를 로고 아이콘이 이미 브랜드를 나타내므로 "통계"로 줄였다. `RatingHistoryChart`에 x축·y축 선과 3단(최저/중간/최고) 그리드+눈금 라벨, 선 아래 반투명 영역 채우기(선 색과 동일 색, opacity 0.16)를 추가하고, 그래프 위에 최근 1주/1달/6개월/1년 중 고를 수 있는 기간 필터(기존 시간 규정·흑백 필터와는 별개 축)를 얹었다 — 고른 기간에 대국이 2판 미만이면 그래프 대신 안내 문구를 보여준다.

**버그 수정 — 레이팅 그래프 시간 규정 혼합, 엔진 라인 MultiPV 순위 변동 시 재타이핑**
사용자가 보낸 스크린 레코딩으로 두 가지를 더 발견·수정했다. (1) `RatingHistoryChart`가 위 시간 규정 필터가 "전체"일 때 래피드·블리츠·불릿 대국을 시간순으로 그냥 한 선에 뒤섞어 그리고 있었다 — 세 시간 규정은 레이팅 체계 자체가 달라(값 크기가 서로 다름) 뒤섞은 선은 실제 실력 변화가 아니라 그날 어떤 시간 규정을 뒀는지에 따라 요동치는 사실상 무의미한 그래프였다. `timeFilter` prop을 새로 받아, "전체"일 때는 세 시간 규정(대국 2판 이상 있는 것만)을 각자 다른 색 선으로 겹쳐 그리고 범례를 달며, 특정 시간 규정으로 좁혀져 있을 때는 기존처럼 그 하나만 영역 채우기와 함께 보여준다. (2) 엔진 라인이 여전히 "끝까지 안 써진다"는 재보고를 헤드리스 브라우저로 재현한 결과, 같은 포지션에 머물러 있어도(포지션 자체는 안 바뀜) MultiPV 순위가 흔들릴 때마다(탐색 초반 흔함) `EngineLineRow`/`TypedMoveLine`을 그 줄의 첫 수로 키를 잡고 있어 순위가 바뀔 때마다 그 자리 전체가 언마운트·재마운트되며 타이핑이 처음(빈칸)부터 다시 시작되길 반복하는 게 진짜 원인이었다(직전에 고친 `useEngine` 큐 경합과는 별개의, 새로 발견한 문제). 키를 그 줄의 내용이 아니라 화면상 자리(슬롯 번호, 포지션이 바뀌지 않는 한 항상 같음)로 바꿔, 순위가 바뀌어 다른 수순이 들어와도 같은 컴포넌트 인스턴스가 유지되며 타이핑 진행 상태가 리셋되지 않도록 했다. 사용자가 보낸 영상과 똑같은 포지션(1.e4 c5 2.Nf3 Nc6)에서 순위가 여러 번 뒤바뀌는 동안 헤드리스 브라우저로 재현·검증함.

**버그 수정/UI — 레이팅 그래프 색 필터 무관화, 오프닝 표시 개편, 자주 두는 첫 수 흑 박스 2열화**
레이팅은 흑/백 어느 색으로 뒀든 하나로 합산 적용되므로 색 필터와 무관해야 하는데, `RatingHistoryChart`가 `AccountChessStats`의 색 필터가 적용된 `games`를 그대로 받아 색을 바꾸면 그래프도 달라지는 버그가 있었다 — 시간 규정만 적용하고 색 필터는 뺀 `gamesForRating`을 별도로 계산해 그래프에는 항상 이것만 넘기도록 분리했다. `TopOpeningsAnimated`(가장 많이 둔 오프닝)에 예전 버전(`TopWhiteMovesAnimated`)에 있던 "백 n수"/"흑 n수" 배지를 되살려 지금 몇 번째로 많이 둔 오프닝을 보여주는 중인지 표시하고, 흑 쪽의 기존 "흑 오프닝 레파토리" 텍스트 라벨은 이 배지로 완전히 대체했다. 오프닝 이름 글자 크기를 16→13px로 줄여 긴 이름(예: "Sicilian Defense: Najdorf Variation, English Attack")도 2줄 안에서 잘리지 않고 온전히 들어가게 했다. `FirstMovesDisplay`의 흑 박스도 개편했다 — 백의 각 첫 수(e4/d4/c4/Nf3)에 대한 흑의 응수를 한 줄에 하나씩 세로로 4줄 늘어놓던 것을, 한 줄에 두 항목씩 2x2 그리드로 배치해 2줄로 줄이고 박스 자체의 폭도 함께 줄였다.

**버그 수정 — 다음 수 블록과 현재 수 블록의 수 키워드(TOP LEVEL 등) 불일치**
다음 수 블록(`MoveTile`)은 `useMergedMoves`가 만든, 마스터/Lichess 채택률이 채워진 "지금 포지션의 다음 수" 객체로 `deriveKeywords`를 불러 키워드를 표시하는데, 그 수를 실제로 두면 현재 수 블록은 한 칸 전 포지션을 `snapNode`(채택률 필드가 없는 정적 북 데이터)로 다시 조회해 같은 함수를 불러 전혀 다른 입력으로 다른 결과를 냈다. 이미 있던 `pinnedKindRef`(블록에 뜬 등급을 pin해 두는) 패턴을 그대로 따라 `pinnedKwRef`를 추가 — 블록에 실제로 떴던 키워드 배열(순서까지)을 "포지션 key + 수"로 pin해 두고, 현재 수 블록은 그 값을 그대로 재사용해 두 곳이 절대 어긋나지 않는다.

**기능 — 집중학습 chess.com 통계 필터, 검색/리뷰 버튼 크기 통일**
집중학습(`FocusPanel`)의 "이 수가 두어진 내 대국" 목록에도 프로필 카드와 동일한 시간 규정(전체/래피드/블리츠/불릿)·진영(전체/백/흑) 선택 박스를 추가했다. 이 목록의 "대국 보기" 버튼이 28px로 옆의 리뷰 버튼(`BestMoveJumpButton`, 30px)과 미묘하게 크기가 달랐던 것을, 프로필 카드·마스터 대국 목록과 같은 30px로 통일했다.

**기능 — 모바일 집중학습 미니보드 하단 2페이지 구성**
집중학습은 전체화면 오버레이(`position:fixed,inset:0`)라, "다음 수" 블록 목록(전체/마스터·평가치순/채택률순 선택 포함)이 그 뒤에 완전히 가려 실제로는 볼 방법이 없었다(특히 모바일에서 두드러짐 — 오버레이 자체가 화면 전체라 더 스크롤할 여지가 없다). 이 블록 목록 JSX를 `nextMovesContent`로 뽑아 `FocusPanel`에 prop으로 넘기고, 미니보드 하단(chess.com 통계+마스터 대국 / 다음 수 블록)을 새 `FocusBoxPager` 컴포넌트로 2페이지에 나눠 담았다 — 페이지 전환은 드래그 또는 ‹/› 버튼으로만 되고(휠·트랙패드 스크롤에는 반응하지 않는 transform 기반 캐러셀), 각 페이지는 `ResizeObserver`로 실측한 자기 콘텐츠 높이만큼만 차지한다(기본 flex의 `align-items:stretch`로 두 페이지 중 더 긴 쪽에 맞춰 짧은 페이지 아래로 빈 공간이 크게 남던 문제를 이렇게 고쳤다).

### OpenChess v0.2.5 — 2026/7/24

**버그 수정 — 엔진 라인·기보 데스크톱 드래그 스크롤**
`EngineLines`의 각 줄(수순 텍스트)이 화면 폭보다 길면 `overflow-x:auto`로만 스크롤을 처리하고 있었는데, 이는 `WebkitOverflowScrolling:touch`가 붙어 터치 기기에서는 자연스럽게 관성 스크롤이 되지만 데스크톱 마우스로는 얇은 스크롤바를 정확히 붙잡거나 shift+휠을 써야만 스크롤이 가능해 사실상 마우스로는 스크롤이 거의 안 됐다 — 뒷부분 수순이 항상 가려진 채 "끊긴" 것처럼 보이는 원인이었다. `EngineLines`를 줄마다 독립된 `EngineLineRow` 컴포넌트로 쪼개고, 포인터 이벤트(`pointerdown`/`pointermove`/`pointerup`, `setPointerCapture`)로 직접 `scrollLeft`를 옮기는 드래그 스크롤을 구현해 마우스·터치·펜 어디서나 동일하게 동작하게 했다. 기존엔 줄 전체에 `onClick`을 걸고 `pointerdown` 시점의 clientX와 `click` 시점의 clientX 차이(`dx<6`)로 드래그와 클릭을 구분했는데, 이 방식은 실제 스크롤 동작 자체가 없어 사용자가 스크롤을 시도하며 끌다 손을 뗀 것도 종종 짧은 드래그로 오인해 클릭(수 두기)으로 처리되곤 했다 — 이제 실제로 픽셀 단위로 끌었는지(`moved` 플래그, 3px 임계값)를 기준으로 스크롤과 클릭을 구분해, 스크롤 의도로 끈 경우엔 절대 수가 두어지지 않고 제자리 클릭에서만 그 줄의 첫 수를 둔다. 같은 패턴을 학습 탭 상단 `SequenceBar`(기보)에도 적용했는데, 여기는 줄 전체가 아니라 수마다 개별 `span`에 `onJump` 클릭이 걸려 있어 캡처 단계(`onClickCapture`)에서 드래그 여부를 먼저 판정해 실제로 끌었으면 그 클릭을 막는 방식으로 구현했다(버블링 전에 가로채므로 어떤 수를 클릭했든 안전).

**버그 수정 — 엔진 라인 타이핑 도중 자동 추적**
위 드래그 스크롤 자체는 됐지만, 타이핑 효과(`TypedMoveLine`)로 수순이 시야보다 길게 자라나도 `scrollLeft`가 그대로 0에 머물러 있어 새로 타이핑되는 뒷부분이 화면 밖에서 계속 이어지기만 할 뿐 사용자 눈에는 여전히 특정 수에서 멈춘 것처럼 보였다 — 사용자가 직접 끌어야만 그 뒤를 볼 수 있었던 게 실제 원인이었다. `ResizeObserver`로 줄의 실제 콘텐츠 폭이 자랄 때마다, 채팅창 자동 스크롤과 같은 패턴으로 지금 보이는 오른쪽 끝이 이미 콘텐츠 끝(atEnd)이었다면 새로 타이핑되는 글자를 계속 따라가며 자동으로 스크롤하도록(`followRef`) 했다. 사용자가 직접 드래그해 앞부분을 살펴보는 중에는 그 위치를 존중해 자동 추적을 멈추고(드래그 종료 시 스크롤 위치가 다시 끝이면 추적 재개), 줄 정체성(포지션+순위)이 바뀌면 처음부터 추적을 재개한다. 아직 안 보이는 수순이 남아 있으면 줄 오른쪽 끝에 옅은 그라데이션 페이드도 표시해 "더 있음"을 시각적으로 알려준다.

**기능 — 티어 여정 지도 배경 이미지 교체**
개발자가 GitHub 웹 UI로 티어 배경(`tier-bg-*`) 원본을 화질이 더 좋은 새 파일로 직접 업로드(webp 삭제 후 png 추가, `main`에 직접 반영된 것을 이 브랜치에 머지)함에 따라, `TIER_BG_IMAGE`의 확장자 참조를 `.webp`에서 `.png`로 맞춰 갱신했다. 예전에 지워졌던 `tier-bg-iron.webp` 자리에도 `tier-bg-iron.png`가 새로 채워져, 아이언 구간 배경도 다시 정상적으로 표시된다.

### OpenChess v0.2.4 — 2026/7/24

**기능 — 게임 리뷰/분석 엔진 분리**
설정 탭의 단일 "분석 엔진" 선택지를 학습 탭·퍼즐 탭·사이트 전반에 쓰이는 "분석"과 게임 리뷰 전용으로 나눴다. 게임 리뷰는 사용자 선택과 무관하게 항상 `ENGINE_PROFILES.full`(Stockfish 16)로 고정하고, `UCI_LimitStrength`/`UCI_Elo=3270`을 새로 보내 사람 최상급 수준으로 세기를 제한한다(`eloSetoptions`, `useEngine`의 boot 시퀀스와 `bootAnalysisWorker` 둘 다에 적용). 분석 엔진 선택지는 Stockfish 18 Lite(기본, 기기 종류와 무관하게 고정)와 17.1 두 가지로 좁히고, 각 엔진의 텍스트 설명(`desc` 필드)을 전부 제거했다. 분석 엔진의 스레드 수는 코어 수 비례(`cores-1`) 대신 2로 고정. 게임 리뷰 핵심 분석(`analyzeGame`, 엔진 라인 패널, 수 판정)은 depth 20·moveTime 상한 1초로, 학습 탭 "엔진 상위 수" 패널은 depth 20·MultiPV 7(movetime 700ms는 체감 속도 유지를 위해 그대로)로 조정했다.

**성능 — 게임 리뷰 로딩 지연 제거**
`ReviewPage`가 안 쓰이던 `useEngine("full")` 상시 연결 대신, 풀 부팅이 통째로 실패할 때만 지연 부팅되는 폴백(`useReviewEngine`)을 쓰도록 바꿔 리뷰당 중복 wasm 컴파일을 제거했다. `getAnalysisPool`의 캐시를 프로필 하나만 유지하던 단일 슬롯(`analysisPoolCache = {profile, promise}`)에서 프로필별 `Map`으로 바꿔, 학습 탭(lite/full17)과 게임 리뷰(full) 풀이 서로 다른 프로필이라는 이유만으로 상대 풀을 매번 통째로 정리하고 재부팅하며 서로를 밀어내던(thrashing) 버그를 발견해 함께 고쳤다. 앱 유휴 시간(`requestIdleCallback`)에 게임 리뷰용 Stockfish 16 풀을 미리 부팅해 두는 프리페치를 추가하고, `vercel.json`에 `/engine/*` 정적 파일 장기 캐시 헤더(`public, max-age=604800, stale-while-revalidate=604800`)를 달아 재방문 시 재검증 왕복을 없앴다.

**기능/성능 — 집중 학습 depth 20 및 엔진 큐 취소**
집중 학습(`useFocusAnalysis`)의 두 평가 경로(수 체계 아이콘, 실수 분석)를 depth 20·moveTime 5초 상한으로 올렸다. 아이콘 판정은 이제 depth가 깊어질 때마다(`onProgress`) 다시 매겨져 최대 5초 동안 여러 번 바뀔 수 있다(단발성 결과 대신 점진적 스트리밍). 실수 분석은 라인마다 공통 시작 포지션을 반복 평가하던 중복 호출도 제거했다. 별도로, `useEngine`·`bootAnalysisWorker`의 작업 큐에 slot 기반 취소(`supersede`)를 도입했다 — 같은 slot의 새 요청이 오면 이전 요청을 즉시 큐에서 빼거나(대기 중) "stop"으로 중단시킨다(실행 중). 이전에는 `cancelled` 플래그가 결과 반영만 막을 뿐 엔진의 실제 작업 큐는 그대로 둬, 긴 기보에서 수를 빠르게 연타해 넘기면 이미 지나간 포지션의 계산이 큐를 막아 다음 요청을 지연시켰다 — 학습 탭 엔진 라인 패널·집중 학습·게임 리뷰의 엔진 라인/수 판정에 slot을 적용해 해결했다. slot을 넘기지 않는 기존 호출(`analyzeGame` 등 배치 분석)은 그대로 FIFO로 전부 처리된다.

**버그 수정 — 게임 리뷰 평가치 일관성**
`analyzeGame`이 포지션마다 병렬 워커로 독립적으로 다시 검색하다 보니, 최선 수를 그대로 뒀을 때(손실 0으로 채점)도 다음 포지션의 재검색 값이 이번 포지션 최선수 평가치의 정확한 부호 반전과 조금씩 어긋나(같은 depth·movetime 목표라도 실제 도달 depth가 매번 조금씩 달라질 수 있음) 그래프·코치 카드 평가치가 흔들려 보였다. 최선 수를 따라간 구간은 다음 포지션의 cp를 이번 포지션 값에서 부호만 뒤집어 이어받도록 해 일관된 값이 나오게 했다(다음 수 채점에 쓰는 최선수·2순위는 독립 검색 결과를 그대로 유지, `graphCp` 계산을 채점 루프 뒤로 옮겨 보정된 값을 반영). 리뷰 자유 탐색에서도 같은 클래스의 버그가 있었다 — 화면에 보여준 추천 수(Show 화살표·엔진 라인 1순위)를 그대로 뒀는데도 재검색이 다른 1순위를 내놓아 "우수한 수"로 오판정되던 것을, `playFree`에서 "지금 보여준 추천과 일치하는 수를 뒀는지"를 `forcedBestRef`로 기록해 뒀다가 채점 시 신뢰하는 방식으로 고쳤다.

**버그 수정 — 엔진 라인 타이핑 멈춤**
`EngineLines`의 각 줄이 배열 인덱스(`i`)로 key/`posKey`를 잡고 있어, MultiPV 순위가 바뀌면(탐색 depth가 깊어지며 흔함) 다른 수순이 같은 자리에 들어와도 `TypedMoveLine`이 재사용돼 이전 수순만큼 이미 진행된 `shown` 값을 그대로 물려받았다 — 새 수순이 그보다 짧으면 그 자리에서 타이핑이 멈춘 것처럼 보였다. key를 수순의 정체성(첫 수)으로 바꿔 순위가 바뀌어도 각 수순이 독립적으로 진행 상태를 유지하게 했다.

**UI — 학습 탭 수 블록 재정렬 애니메이션**
`useMergedMoves`의 `tiled` 정렬이 실시간 평가 스트리밍으로 순위가 바뀌어도, 렌더링이 plain `.map()`(key만 안정적)이라 React가 DOM을 순간이동시킬 뿐이었다. 이미 있던 `FadeIn`(`motion.div layout`) 컴포넌트로 `MoveTile`을 감싸 FLIP 애니메이션이 붙게 했다.

**버그 수정 — "?" 탐색 depth 표시**
평가치 바 옆 "?" 도움말의 depth 숫자(`curDepth`)가 메인 검색(depth 20 목표)과 개별 후보 수 평가(depth 15 고정, 즉각 반응 유지 목적으로 그대로 둠) 두 진행률을 같은 값으로 합쳐 표시하고 있었다. 후보 수가 많은 포지션일수록 depth 15 검색들이 자주 완료되며 그 값을 계속 15로 밀어붙여, 메인 검색의 실제 진행 상황이 15에서 멈춘 것처럼 가려 보였다 — 후보 수 개별 평가는 표시용 depth에 더 이상 반영하지 않도록 분리했다.

**기능 — 리체스 퍼즐 DB 기반 오늘의 퍼즐**
기존 "오늘의 퍼즐"은 하드코딩된 4개짜리 배열에서 날짜를 시드로 결정적으로 뽑는 완전 클라이언트 사이드 기능이었다. 리체스 퍼즐 데이터베이스(`database.lichess.org`, 라이브 API가 아니라 CSV 통짜 덤프)를 오프닝 테마별로 활용하도록 새로 만들었다 — `scripts/build-daily-puzzles.mjs`(신규 devDependency `chess.js`)가 CSV를 오프닝 태그로 필터링하고, 각 후보의 원본 대국 PGN을 리체스 게임 export API에서 받아 시작 위치부터의 SAN 수순(`setupSans`)으로 복원해 `public/daily-puzzles/<태그>.json`을 만든다(스트리밍 라인 리더로 읽어 1~2GB급 CSV도 메모리 문제 없이 처리; `scripts/peek-puzzle-tags.mjs`로 실제 태그 표기를 사전 확인 가능). 리체스 퍼즐 자체는 정답이 한 줄뿐이지만, 런타임에 실제 엔진으로 `genPuzzleTree`를 돌려 상대의 다른 응수까지 포함한 여러 라인을 만들고 그중 한 줄을 다시 날짜 시드로 뽑아 `XXXXXX-N`(N=그 줄의 순번) 형태의 id를 부여한다(`resolveDailyPuzzle`). 신규 Supabase 테이블 `daily_puzzle_themes`(2주 오프닝 테마 로테이션, 개발자가 그때그때 지정)와 `daily_puzzles_dev`(미래 날짜 퍼즐을 PGN으로 직접 지정) — 둘 다 `master_games_dev`와 동일한 `is_content_editor` RLS 이중 검증 패턴. `useDailyPuzzle` 훅이 비동기 계산이 끝나기 전엔 기존 큐레이션 폴백(`curatedDailyPuzzleFor`)을 보여줘 화면이 비지 않게 한다. id 형식이 `daily_YYYY-MM-DD`에서 `XXXXXX-N`으로 바뀌어, "어제 이전의 오늘의 퍼즐" 복원 방지 로직을 id 접두사 대신 퍼즐 객체의 `isDaily`/`date` 필드로 판정하도록 함께 수정했다(구버전 저장값은 접두사 검사로 폴백). 설정 탭에 개발자 전용 관리 패널(`DailyPuzzleDevPanel`)과 퍼즐 탭에 "지난 오늘의 퍼즐" 목록(`PastDailyPuzzles`, 순수 함수+결정적 시드라 과거 날짜도 그대로 재현 가능)을 추가했다. XP는 기존 라인 솔브 로직을 그대로 재사용한다.

### OpenChess v0.2.3 — 2026/7/24

**버그 수정 — 탁월한 수(brilliant) 판정**
`isSacrifice`가 4가지 오판정을 내고 있던 것을 실제 대국 4개(사용자 제공 PGN)로 재현·수정함. (1) 내 기물이 방치돼 공격받고 있어도, 그 방치된 기물과 가치가 같거나 더 높은 상대 기물을 안전하게(다음 수에 안 잡히게) 반격 위협하면 탁월로 치지 않도록 `attacksPricierIndependent`를 새로 추가함 — 다만 그 반격 기물이 "도망가면서 동시에" 방치된 내 기물을 잡을 수 있는 경우(예: 9.d5가 나이트 e5의 보호를 없애는 동시에 그 옆 퀸도 위협해, 퀸이 도망가며 그대로 나이트를 챙길 수 있는 경우)는 진짜 반격이 아니므로 예외로 남겨 탁월 판정을 유지함. (2) 원래 `beforeHang>=2 && afterHang>=2`를 동시에 요구해, "이 수 자체가 자신의 보호자를 옮겨서 처음으로" 다른 기물이 방치되는 패턴(beforeHang=0)을 전혀 잡아내지 못했다 — `afterHang>=2`만으로 게이트를 완화함. (3) 포크에 걸린 기물을 옮겨 위험을 줄이기만 했을 뿐인데(방치된 기물의 손실이 원래 포크 손실보다 작음, 22.Qe3 예시) 우연히 무관한 기물이 방치돼 있었다는 이유로 탁월로 오판되던 것을, `afterHang < movedThreatLoss`면 제외하도록 수정함. (4) 이동한 기물이 이미 예정된 손실(movedThreatLoss)을 그대로 실현하는 수는 원래 탁월에서 제외되는데, 그 수가 체크를 동반하는 경우(36.Nh6+처럼 상대 응수를 강제하며 콤비네이션의 발판이 되는 수)는 수동적 손실 수용이 아니므로 예외로 둠. `isSacrifice`는 8개 호출부가 공유하는 단일 함수라 이 수정이 학습 탭·리뷰 페이지·집중 학습·퍼즐 전부에 함께 적용됨.

**성능 — PGN 재생 O(n²) 제거**
`boardFromSans`/`sansToFen`이 호출될 때마다 시작 포지션부터 sans 전체를 처음부터 재생해, 학습 탭·리뷰 페이지에서 긴 기보를 두거나 포지션을 빠르게 넘길수록(=진행된 수만큼) 호출 하나하나의 비용이 커지고 이게 누적돼 뒤쪽 수순으로 갈수록 체감 속도가 심각하게 느려졌다. 두 함수가 공유하는 모듈 스코프의 "마지막으로 재생한 경로" 캐시(`replaySans`)를 두고, 새 호출의 sans와 캐시된 경로의 공통 접두사까지는 이미 계산해 둔 보드·캐슬링 권리·앙파상 상태를 재사용, 갈라지는 지점부터만 증분으로 적용하도록 바꿈 — 실제 진행(한 수씩 이동, 같은 위치에서 여러 후보 수 평가)은 대부분 직전 호출과 긴 공통 접두사를 공유하므로 실질 비용이 거의 O(1)에 가까워짐. 이 두 함수를 쓰는 20여 개 호출부(엔진 평가·후보 수 계산 등) 전부가 코드 변경 없이 함께 빨라짐. board는 항상 새로 만들어지므로(applySan이 원본을 mutate하지 않음) 캐시가 스냅샷을 들고 있어도 안전함을 board mutation 여부 전수 확인으로 검증함.

**버그 수정 — 리뷰 페이지 평가치 변동**
`/review` 자유 탐색 중 포지션이 바뀌어도 `engineLines`가 이전 값을 그대로 유지한 채(새 계산이 끝날 때까지) 그대로 두고 있어, `activeEvalDisp`가 새 계산이 끝나기 전까지 이전 포지션의 평가치를 보여주다 계산이 끝나는 순간 새 값으로 튀는 것이 "최선의 수를 뒀는데 평가치가 변동한다"는 증상으로 보였다. 학습 탭(`useMergedMoves`)은 같은 상황에서 `barEval` 계산부가 `linesPending` 중엔 `engineLines`가 아니라 별도의 빠른 단일PV 진행 콜백(`posEval`)을 쓰도록 분리해 두어 이 문제가 없었는데, 리뷰 페이지엔 그 분리가 없었다 — 새 계산을 시작하는 즉시 `engineLines`를 비워, 화면에는 항상 지금 포지션의 값(또는 계산 중)만 보이게 함.

**버그 수정 — 채점 기준 통일**
리뷰 페이지의 자유 탐색 판정(exploreMove)이 depth 14·movetime 700ms를 쓰고 있어 학습 탭(`evalMoveKind`, depth 13·`MOVETIME_MS` 260ms)과 같은 위치·같은 수에 다른 등급이 나올 수 있었다 — `MOVETIME_MS`를 모듈 스코프 상수로 승격해 depth·movetime을 통일함. 언더프로모션(=/=Q 아닌 승진)을 탁월로 완화하는 규칙이 학습 탭에는 있는데 리뷰 자유 탐색과 정식 게임 리뷰(`analyzeGame`)에는 빠져 있던 것도 양쪽에 동일하게 추가함.

**기능 — 스테일메이트·3회 동형 반복 무승부**
`gameEndState(sans)`를 새로 추가해 스테일메이트·체크메이트·3회 동형 반복(국면 반복 비교는 기물 배치+다음 차례만 보는 단순화된 키를 사용) 여부를 판정함. 체크메이트는 `legalDests`가 이미 자연히 더 이상의 수를 막지만, 3회 동형 반복은 규칙상 여전히 "합법적으로 둘 수 있는" 수가 남아 있어 게이팅이 없으면 계속 둘 수 있었다 — 학습 탭 `go()`, 리뷰 페이지 `playFree()` 양쪽에 이 판정을 넣어 스테일메이트·3회 반복 국면에서는 더 이상 수를 둘 수 없게 하고 보드 하단에 원인을 표시함. chess.com 최근 대국·친구 프로필 목록의 "무" 표시에도 `drawKindLabel`로 실제 기보를 재생해 스테일메이트/3회 동형 반복이면 그 이름을, 아니면 "합의 무승부"를 괄호로 덧붙임.

**기능/UI**
티어 승급 시(`tierUpAnim` 트리거 시점) 새로 도달한 티어 인덱스 × 50개의 나이트 OC 코인을 지급하고 기존 코인 토스트로 알림. 티어 여정 지도의 닫기 버튼을 스크롤되는 콘텐츠 밖으로 빼 `position:fixed`로 우상단에 고정. 학습 탭 메인 보드에서 잡힌 기물·기물 점수차 표시를 제거(`BoardWithMaterial`에 `hideMaterial` prop 추가, 리뷰 페이지는 그대로 유지). 집중 학습 미니보드(`AnimatedMove`)에서 금색(idea)·빨간색(danger) 화살표가 같은 두 칸을 잇는 경우, 그 그룹을 찾아 중심선 기준 대칭으로 수직 평행이동시켜 겹치지 않게 함. 일일 퍼즐 — `puzzleActive`가 새로고침 시 localStorage에서 그대로 복원되는데, 어제 오늘의 퍼즐(id: `daily_YYYY-MM-DD`)을 열어본 채로 자정을 넘기면 그 stale한 값이 계속 복원돼 퍼즐 탭 첫 화면이 전날 퍼즐로 보이던 버그 — 복원 시 그 id가 오늘 날짜가 아닌 `daily_`로 시작하면 복원하지 않도록 수정.

**기능 — 마스터 대국 데이터 소스**
마스터 대국을 chessgames.com 데이터로 대체할 수 있는지 검토함 — chessgames.com은 공개 API가 없어(문서화된 개발자 접근 경로 부재) 자동 연동이 불가능함을 확인함. 대신 개발자 권한(`is_content_editor`, 기존 `app_content` RLS와 동일 헬퍼 재사용)으로 마스터 대국을 직접 등록하는 기능을 추가함 — `master_games_dev` 테이블(RLS: 읽기는 전체 공개, 쓰기는 개발자/공동개발자만)을 신설하고, 집중 학습의 "이 수가 두어진 마스터 대국" 옆에 개발자 전용 `+` 버튼으로 단일 대국 등록(백/흑 GM 이름+레이팅, 연도, PGN — 결과는 PGN의 결과 토큰 또는 마지막 수의 `#`로 자동 판정) 또는 여러 대국이 이어 붙은 PGN(PGN Mentor 등에서 받은 파일) 대량 가져오기(`splitPgnGames`+`parsePgnGameForImport`가 `[Event`를 기준으로 대국을 쪼개고 표준 헤더 태그로 자동 채움, `addDevMasterGamesBulk`가 200개씩 묶어 PostgREST 배열 insert)를 지원함. 등록된 대국은 `fetchAllMasterGames`가 Lichess 마스터 DB 결과와 합쳐 반환해 출처 구분 없이 같은 목록에 표시됨. `master_games_dev` 테이블·정책은 저장소의 `supabase-setup.sql`에만 추가돼 있고, 실제 프로젝트 DB에는 별도로 SQL을 실행해야 반영됨.

### OpenChess v0.2.2 — 2026/7/23

**성능**
학습 탭의 엔진 라인(엔진 상위 3줄)이 확정되기까지의 벽시계 시간을 크게 줄임. `useMergedMoves`에서 평가치 바·엔진 상위 3줄·후보 수 보충을 하나로 통합한 `evaluateMulti(depth 16, MultiPV-10)` 호출의 `movetime` 상한을 3000ms에서 700ms로 낮춤 — 엔진 라인은 이미 `streamLines`로 depth가 깊어질 때마다 실시간으로 흘러 나오므로 사용자가 체감하는 "라인 계산 시간"은 이 상한이 결정한다. 평범한 학습·오프닝 포지션은 이 시간 안에 목표 depth에 이미 도달해 표시가 그대로이고, 유독 오래 걸리던 복잡한 포지션만 0.5~0.7초 안에서 (그 시점의 충분히 깊은 라인으로) 확정돼 대기감이 사라짐. 개별 후보 수(`MoveTile`) 평가는 아래에서 여전히 독립된 depth 15 검색으로 채워지므로 수 블록 정확도에는 영향이 없다.

**버그 수정**
학습 탭에서 "다음 수 블록"(`assignTiers`로 매긴 후보 수 등급)에 표시된 수 체계 아이콘과, 그 수를 실제로 뒀을 때 체스판 도착칸·"현재 수 블록"(`curKind`)에 뜨는 아이콘이 서로 다르게 보이던 문제를 해결함. 원인은 두 곳이 서로 다른 분류 알고리즘을 쓴 것 — 후보 블록은 형제 수들의 평가치를 기준으로 판정하는 `assignTiers`(`only`/최선 argmax 로직 포함)를, 실제 둔 수는 마지막 수 재평가 `useEffect`가 별개 알고리즘인 `evalMoveKind`(새 depth 검색으로 판정하고 `decided` 완화·언더프로모션→탁월·`only` 미생성 등 규칙이 다름)로 매번 다시 계산해 `stampQ`가 세팅한 후보 등급을 덮어썼다. 블록에 실제로 떠 있던 각 수의 확정 등급을 `pinnedKindRef`(`"이 위치 key|수"` → 등급)에 pin해 두고(후보 목록이 갱신될 때마다, 그리고 블록에서 수를 고르는 `stampQ` 시점에도 즉시 기록), 마지막 수 재평가 effect가 그 수의 pin이 있으면 `evalMoveKind` 재계산 대신 pin된 등급을 그대로 쓰도록 함 — 클릭·드래그·엔진 라인 클릭·앞으로/되돌리기 어느 경로로 그 수에 도달하든 다음 수 블록과 정확히 같은 아이콘으로 보인다(보드 badge와 `curKind`는 둘 다 `lastQ`에서 파생되므로 한 곳만 맞추면 함께 일치).

- 학습 탭 제안 화살표: 이론 수뿐 아니라 모든 후보 수로 범위를 넓히고, 선택된 정렬 기준(평가치순/채택률순)으로 상위 3수만 표시. 예전엔 두께·투명도가 "평가치순"을 선택해도 항상 채택률(adopt) 기준으로만 계산되던 버그도 함께 수정(`weight` 필드로 일반화).
- 리뷰 코치 카드: 탁월한 수 설명에 실제로 희생한 기물을 명시(`sacrificedPieceKor` — 방금 이동한 기물 자신이 공격받으면 그 기물을, 아니면 가장 크게 걸린 다른 기물을 찾음). 평가치 박스를 반투명 흰 배경+아이보리 텍스트에서 `EvalBadge`(유리한 쪽에 따라 흰색/검은색 반전)로 통일.

> 남은 작업(v0.2.2): `/about` 소개(1페이지) 최신 내용·스크린샷 갱신과 버전 기록 사이 스크린샷/상호작용 요소 추가는 최신 버전 스크린샷 업로드 후 진행 예정(UI#1).

`useChessCom`이 대국마다 로그인 유저의 진영(`side`)만 남기고 상대 쪽 정보는 버리고 있었다 — chess.com 원본 API 응답(`g.white`/`g.black`)엔 원래 양쪽 다 있으므로, 이제 양쪽의 실제 닉네임·그 대국 당시 레이팅을 그대로 저장함. 프로필의 "최근 대국" 목록에 상대 닉네임·레이팅을 추가하고, `/review`의 요약 화면·Analysis·Details 탭에서도 `reviewPlayerInfo(game, side)` 헬퍼로 실제 이름을 우선 쓰되(없으면 "나"/"상대", 그마저 없는 임의 수순 분석은 "백"/"흑")로 단계적으로 대체함.

`Board`를 감싸는 `BoardWithMaterial` 래퍼를 새로 만들어(Board 자체의 prop 계약은 그대로 둠), 시작 기물 수와 현재 보드에 남은 기물 수를 비교하는 `capturedInfo(board)`로 학습 탭 메인 보드와 `/review`(모바일·데스크톱 둘 다)에 잡힌 상대 기물 아이콘과 기물 점수 차이를 표시함 — 점수가 동등하면 숫자는 아예 안 뜨고, 유리한 쪽에서만 `+n`으로 표시됨.

일일 퍼즐 기능 추가 — 매일 KST 자정 갱신되는 큐레이션 퍼즐(Fool's Mate·Scholar's Mate·Légal's Mate·Blackburne Shilling Gambit, 4종 모두 자체 체스 로직으로 합법성 검증 후 등록)을 `seedRand("daily:"+dateStr)`로 결정적으로 하나씩 순환시킴(`dailyPuzzleFor`). 퍼즐 탭 상단에 `TodayPuzzleCard`를 추가하고, 일일 최초 접속 시 1회, 오늘의 퀘스트를 아직 못 끝냈다면 3시간마다 `DailyPuzzleNoticeModal`(오늘 하루 다시 보지 않기 체크박스 포함)을 띄움.

업데이트 공지 모달을 "버전당 최초 접속 시 1회만" 뜨도록 고침 — 예전엔 "다시 보지 않기" 체크박스를 직접 체크해야만 확정됐는데, 이제 닫는 방법과 무관하게 `onClose`에서 곧장 `dismissedAnnounceVersion`을 확정한다. 같은 내용(버전·날짜·항목)은 설정 탭의 개발진 박스 안에 "개발자 기록"으로 상시 열람 가능하게 남기고, `CHANGELOG` 각 항목에 `dev: [...]`(참여 개발자 아이디) 필드를 추가함.

분석 엔진 선택지에 Stockfish 17.1(정식 대형 신경망, 세 엔진 중 최고 성능)을 추가함 — 같은 npm 패키지를 여러 버전으로 동시에 설치할 수 없어 `stockfish171`(`npm:stockfish@17.1.0`) 별칭으로 받고, `scripts/copy-engine.mjs`가 npm 배포 용량 제한 때문에 여러 조각(`-part-N.wasm`)으로 쪼개진 신경망 파일들과, `self.enginePartsCount`를 먼저 정의한 뒤 실제 엔진 스크립트를 `importScripts`하는 부트스트랩 스크립트(`boot-single.js`/`boot-mt.js`)를 생성하도록 확장함. 로더 스크립트가 조각 파일명을 "자신을 실행 중인 워커의 location"에서 유추하는데, 부트스트랩 파일의 실제 경로로는 엉뚱한 이름을 찾다가 실패했다 — 워커 생성 URL에 `#진짜파일명.wasm` 해시를 붙여(로더가 `self.location.hash`를 우선 사용) 정확한 조각을 찾도록 수정함.

**성능**
실시간 수 아이콘(`evalMoveKind`)과 게임 리뷰(`analyzeGame`) 둘 다 필요할 때마다 워커를 새로 띄우고 끝나면 버렸다 — 매번 신경망을 처음부터 다시 컴파일해야 해서, 특히 신경망이 큰 프로필(17.1)일수록 부팅 비용이 목표 응답 시간보다 커지기 쉬웠다. 프로필별로 딱 한 번만 띄워 세션 내내 재사용하는 공용 워커 풀(`getAnalysisPool`)을 도입하고, 엔진을 바꾸면(다른 profile 요청 시) 이전 풀만 정리하도록 함. `evalMoveKind`는 "두기 전"/"둔 뒤" 포지션이 서로 독립적인데도 순차로 평가하던 것을 풀에서 워커 두 개를 받아 완전히 병렬로 처리하도록 바꾸고, depth(13)에 movetime 260ms 안전 상한(이 depth에서 사실상 항상 여유 있게 끝남 — 정확도 손실이 아니라 워치독 성격의 상한)을 추가함. 워커 풀 크기는 프로필별 고정 상한(예: lite=4) 대신 기기 코어 수(`navigator.hardwareConcurrency`)만큼 그대로 쓰도록 바꿈(발열·CPU 점유율은 감수, 안전을 위한 극단적 상한 32만 유지).

학습 탭 후보 수 블록(`useMergedMoves`) 생성이 같은 포지션 하나를 depth16 단일PV(평가치 바) → depth15 멀티PV-3(엔진 상위 3줄) → depth13 멀티PV-10(후보 수 보충) 순서로 메인 엔진에 세 번 연달아 물어보고 있었다 — 셋 다 "같은 포지션의 상위 수순"이라는 같은 정보를 서로 다른 depth·개수로 중복 탐색하던 것이다. Stockfish의 MultiPV는 한 번의 탐색으로 원하는 개수만큼의 최상위 수를 동시에 주므로, 한 번의 MultiPV-10 탐색(depth 16, movetime 3000ms)으로 통합함 — 이를 위해 `evaluateMulti`에도 단일PV 탐색처럼 depth가 깊어질 때마다 진행 상황을 보고하는 `onProgress` 콜백(1순위 줄 기준)을 새로 추가함. depth·정확도는 그대로 두고 중복 탐색만 없애 벽시계 시간을 최대 3분의 1 가까이로 줄였고, 겹치는 수의 평가치가 서로 다른 탐색에서 미세하게 갈려 블록과 엔진 라인 표시가 어긋나던 문제도 부가적으로 해소됨. 계산 중에는 `linesPending` 플래그를 재사용해 "MILKU/KOKOA가 수를 계산하고 있어요" 마스코트 안내를 표시함.

**버그 수정**
평가치 막대의 탐색 도움말(?) 아이콘이 흰색이라, 백이 크게 우세해 막대가 거의 다 흰색이 되면 배경에 묻혀 안 보이던 문제 — 테마 중립색(브라스 골드)으로 변경함.

프로필에 연동한 chess.com 아이디의 대소문자 표기가 실제와 다르게 보이던 문제 — chess.com API가 소문자로 정규화한 필드를 그대로 썼던 것이 원인이며, `url` 필드에서 실제 표시 대소문자를 추출하도록 근본 수정함.

방치 희생(neglect sacrifice) 기반 "탁월한 수" 판정이 캐슬링·폰 이동에서 전혀 작동하지 않던 구조적 버그를 수정함.

모바일에서 "문의하기"를 눌러도 메일 양식에 제목·본문이 채워지지 않거나 메일 창 자체가 안 뜨던 문제 — Gmail 웹 작성 화면 URL을 새 탭으로 열던 방식 대신 표준 `mailto:` 링크로 교체해 운영체제 기본 메일 앱이 항상 제목·본문까지 채운 채 열리도록 함.

일일 퍼즐 알림 팝업과 업데이트 공지 모달이 동시에 뜰 때, 나중에 마운트된 알림 모달의 전체화면 배경(z-index가 같아 뒤 모달을 완전히 가림)이 공지 모달의 닫기 버튼을 가려 못 누르게 만들던 문제 — `announceOpen` React state(다른 effect가 갱신해야 반영되는 값이라 같은 커밋 안에서 지연이 생김) 대신, 그 값을 결정하는 원본 조건(`dismissedAnnounceVersion !== APP_VERSION`)을 직접 계산해 지연 없이 순서를 보장하도록 수정함.

Stockfish 17.1 워커가 분할된 신경망 조각(wasm part) 이름을 찾지 못해 매번 "연결 실패"로 이어지던 문제(위 "기능" 항목 참고)를 부트스트랩 워커 URL의 해시 트릭으로 해결함.

개발자 모드 XP 조작이 실제 게임(티어 배지·승급 연출·그랜드마스터 스킨)에 정상 반영되는지 조사함 — 렌더링 경로는 전부 정상이었고, 새로고침 시 서버 값이 방금 로컬 변경을 되돌리는 좁은 레이스만 있었다. 두 차례 클라이언트 측 우회를 시도했으나 둘 다 자동 보안 검토에서 "로컬 스토리지 조작으로 서버 XP를 영구 위조 가능"하다는 지적을 받아 전부 원복하고, 원래의 "서버 값을 항상 신뢰" 동작을 그대로 유지함(서버 측 검증 없이는 근본 수정이 불가능하다고 판단).

### OpenChess v0.1.5 — 2026/7/18

**기능**
`/about` 소개 페이지의 체스보드(`DecoBoard`)에 원목 질감(칸마다 결이 보이는 두 겹 그러데이션)과 실제 사이트처럼 파일(a~h)·랭크(1~8) 좌표 표기, 네 모서리가 살짝 어두워지는 비네트를 추가함. 기존에 왕·폰 몇 개만 배치한 추상적 예시 대신, 폴스 메이트·스칼라스 메이트·레갈의 함정·프라이드 리버 어택·불멸의 게임(안더센 vs 키제리츠키, 1851)·오페라 게임(모피 vs 브런즈윅 공작·이수아르 백작, 1858) 6개의 실제 유명 대국·오프닝 함정을 데코 보드 소재로 사용함 — 스크래치패드에 별도 python-chess 스크립트로 각 대국의 SAN 기보 전체를 한 수씩 합법성 검증까지 마친 뒤(6개 전부 완전히 합법이었고 5개는 실제로 체크메이트로 종료) 그 최종 FEN과 마지막 수를 그대로 옮겨 적어, 좌표를 손으로 옮기다 생기는 오차 없이 정확히 재현함(FEN → 보드 배치 변환은 `piecesFromFEN` 유틸이 코드에서 직접 계산).

chess.com 아이콘(`/chess.com_Icon.png`)을 "학습" 기능 카드의 이름표 옆 배지로 추가하고, chess.com 연동 기능(대국 자동 동기화·게임 리뷰 정확도·레이팅 변화 그래프·오프닝별 승률 통계)을 소개하는 별도 섹션(`ChessComSection`)을 신설함 — 실제로 App.jsx에 이미 구현돼 있는 기능만 소개함.

`/about` 페이지의 `VERSION_HISTORY` 배열에서 v0.1.2·v0.1.3 두 버전이 통째로 누락돼 있던 것을 발견해 복구함(README·App.jsx CHANGELOG에는 있었지만 이 배열에만 없었음). 재발 방지를 위해 이 README의 개발 워크플로우 규칙에 "버전 기록 갱신 대상은 README·CHANGELOG·`AboutPage.jsx`의 `VERSION_HISTORY` 세 곳"이라는 항목을 명시적으로 추가함.

집중 학습(FocusMode)에서 퍼즐이 자동 생성되는 동안, 진행률 숫자만 보여주던 것을 실제로 만들어지는 과정을 미리 보여주는 애니메이션으로 바꿈. `genPuzzleTree`의 `onProgress` 콜백이 진행률(p)뿐 아니라 그 순간 막 탐색해 늘어난 수순(path)도 함께 실어 보내도록 하고(`bumpNode(path)`), `puzzleGenProgress` 상태를 `{p, path}` 형태로 바꿔 `FocusPanel`이 `AnimatedMove`로 그 path의 마지막 수를 그때그때 슬라이드시켜 보여준다 — 새 수를 찾을 때마다 미니 보드가 그 수만큼 자라난다.

티어 여정 지도에서 그랜드마스터(마지막·끝없는 티어)가 다른 정거장과 같은 지그재그 자리에 묻혀 "여기가 마지막"이라는 느낌이 없었다 — 그랜드마스터 직전 간격만 크게 벌리고(`GM_EXTRA_GAP`), 그 연결선을 지그재그 대각선 대신 중앙(50%)으로 꺾여 들어가는 긴 꺾은선(엘보)으로 바꾸고, 그랜드마스터 자신도 중앙에 배치함. 위쪽 여백(`GM_TOP_PAD`)도 넉넉히 둬 오로라 배경이 잘리지 않고 길게 보이도록 함.

(중간에 시도했던 손으로 좌표를 짜 넣는 SVG 마스코트 자체 제작안은 스타일이 기존 캐릭터와 맞지 않아 전량 폐기함.)

티어 여정 지도의 티어별 배경이 경계에서 뚝뚝 끊어져 보이던 것을 자연스럽게 이어지도록 함 — 예전엔 밴드마다 자기 영역 안에서만 위아래로 페이드돼, 경계에서 두 배경이 섞이는 대신 둘 다 같은 어두운 배경으로 각자 사라졌다 나타났다. 이제 각 밴드를 이웃 티어 영역까지 `BG_FADE`(130px)만큼 겹쳐 그려, 겹친 구간에서 두 배경이 실제로 서로 섞이며 이어지도록 함(맨 처음 아이언의 아래쪽·맨 끝 그랜드마스터의 위쪽은 겹칠 이웃이 없어 확장하지 않음).

티어 여정 지도 헤더의 "티어 여정"·"퍼즐을 풀어 경험치를 쌓으면 다음 티어로 승급해요" 안내 문구를 없애고, 그 자리에 이정표(Milestone) 아이콘만 남김 — 아래 지도 자체가 이미 지금까지의 여정을 보여주므로 문구 없이도 뜻이 통함.

**UX**
사이트 본편(App.jsx) 전체에서 motion이 티어 여정 지도·승급 연출에만 쓰이고 나머지(퍼즐 카드·퀘스트 카드·상점 카드·친구/검색 목록·알림·채팅 목록)는 전부 즉시 나타나는 정적 div였던 것을 개선함. 카드 컴포넌트 내부는 건드리지 않고 리스트를 그리는 `.map()` 호출부만 새 공용 래퍼 `FadeIn`(`/about`의 `Reveal`과 같은 easing)으로 감싸는 방식을 택해, 좋아요·풀이 상태 같은 기존 로직을 그대로 두면서 인덱스만큼 스태거된 페이드+상승 등장 애니메이션을 얇게 씌움 — 퍼즐 탭 추천/미해결/해결 완료 그리드, 프로필 "푼 퍼즐" 미리보기·"더 보기" 모달, 퀘스트 탭 챕터 목록·메인/일일 퀘스트 카드, 상점 탭 보드·기물 스킨 목록, 유저 검색 결과·친구 추천·리더보드, 친구 목록·요청 목록, 알림 드롭다운, 채팅 목록에 적용함. 목록에서 항목이 사라지는 경우(퍼즐 필터링·친구 요청 수락/거절·알림 삭제)는 `AnimatePresence`로 감싸 갑자기 사라지는 대신 축소되며 부드럽게 퇴장하도록 했고, 알림 드롭다운·채팅 목록 모달·"더 보기" 모달 자체의 열림/닫힘에도 페이드+스케일 전환을 추가함. 채팅 메시지 버블(드래그로 시각 표시하는 기존 제스처가 얽혀 있어 회귀 위험이 큼, 이후 별도 항목으로 손을 댐)과 도감 탭 오프닝 트리(팬·줌 로직이 과거 여러 번 깨졌던 이력)는 이번 범위에서 의도적으로 제외함.

**버그 수정**
그랜드마스터 티어 배지가 오로라 사진으로 잘못 표시되던 문제를 완전히 해결함. `git log --follow`로 `public/grandmaster.png`의 이력을 추적해 원인을 특정함 — 사용자가 GitHub 웹 업로드로 올바른 기물 아이콘을 두 차례(피스만 있는 1.3MB 초안 → 기물+"GM" 워드마크 44KB 최종본) 올렸는데, 이후 같은 파일명으로 오로라 사진이 세 번째로 업로드되며 덮어써졌음. v0.1.3의 커밋(`cfa53d7`)이 "복구했다"고 기록돼 있었지만 실제로는 해당 파일이 손대지지 않아 회귀가 남아 있었던 것도 함께 확인함. 이번엔 파일명 충돌 자체를 없애기 위해 사용자가 두 이미지를 `gm-piece.png`(기물만)·`gm.png`(기물+워드마크)라는 새 이름으로 재업로드했고, `App.jsx`의 `TIER_IMAGE.grandmaster`와 `AboutPage.jsx`의 `TierStrip`이 참조하던 `/grandmaster.png`를 전부 `/gm-piece.png`로 교체함(헤더 배지·여정 지도·퍼즐 탭 스트립·`TierUpOverlay` 승급 연출이 모두 이 값 하나를 공유하므로 한 곳만 고치면 전체가 해결됨 — `tierPieceSrc`로 확인). 워드마크가 포함된 `gm.png`는 작은 배지(`TierBadgeShape`, 76px 십각형)에 넣기엔 텍스트가 안 읽힐 만큼 작아져, 대신 `/about` 버전 기록의 이번 v0.1.4 하이라이트(`ImageHighlight`, 새로 추가한 `VersionHighlight`의 `img` 종류)에서 이 수정 자체를 소개하는 큰 이미지로 사용함.

"여정 지도가 모바일에서 왜곡된다"는 신고를 받아 원인을 추적한 끝에 발견한 근본 버그 — framer-motion은 `scale`/`rotate`처럼 transform 계열 모션 값을 다루는 순간 그 엘리먼트의 `transform` CSS를 자기가 계산한 값으로 통째로 덮어써, 정거장 원(`TierJourneyPath`)에 정적으로 준 `translateX(-50%)` 중앙 정렬이 등장 애니메이션이 끝나자마자 조용히 사라지고 있었다. 데스크톱에서는 여백이 넉넉해 티가 안 났지만, 78% 자리 정거장이 중앙 정렬 없이 그대로 오른쪽으로 반 칸(48px)어치 더 밀려나 좁은 모바일 화면(320px 등)에서는 뷰포트 밖으로 실제로 잘려나갔다(Playwright로 `getBoundingClientRect`를 직접 재 확인해 검증). 정적 중앙 정렬은 애니메이션이 없는 바깥 `div`가 전담하고, scale/rotate 애니메이션은 그 안쪽(inset:0)의 별도 `motion.div`로 분리해 해결함.

사이트 전체 카드·목록에 애니메이션을 넣는 과정에서 두 가지 회귀를 발견해 함께 고침 — (1) `AnimatePresence`의 `popLayout` 모드는 퇴장 애니메이션 동안 레이아웃을 측정하려 직계 자식에 ref를 직접 꽂는데, 공용 래퍼 `FadeIn`이 일반 함수 컴포넌트라 그 ref를 못 받아 "Function components cannot be given refs" 경고가 났다 — `React.forwardRef`로 감싸 해결. (2) 학습 탭 수 블록 목록에서 `key`를 수(san) 문자열만으로 줬더니, `popLayout`이 이전 위치(퇴장 중)와 새 위치(등장 중)의 목록을 잠깐 함께 그리는 동안 같은 수("e4" 등)가 서로 다른 위치에서 우연히 겹쳐 "중복 key" 경고가 났다 — 지금 포지션까지 합친 키로 바꿔 해결. 같은 이유로, "수 추천"/"현재 수" 두 블록이 나란히 같은 위치 문자열을 key로 쓰다 겹친 것도 함께 발견해 구분함. (이후 사용자 요청으로 학습 탭 수 블록·"수 추천"/"현재 수" 카드·집중 학습 진입 애니메이션과 스무스 스크롤은 전부 되돌리고, 퍼즐 생성 실시간 미리보기만 남김.)

**기능 — 채팅 개선**
`ChatPanel`에 실시간 타이핑 표시를 추가함 — DB에 쓰지 않는 Supabase Realtime broadcast 채널(`typing:<uid1>:<uid2>`, 두 uid를 정렬해 대화마다 고정된 채널명을 씀)을 대화 상대와 공유해, 입력창에 글자를 칠 때마다(1.5초 스로틀) `{type:"broadcast", event:"typing"}` 신호만 주고받는다. `broadcast:{self:false}`로 열어 내가 보낸 신호가 나에게 되돌아오지 않으므로, 이 채널에서 받는 이벤트는 항상 상대방 것으로 취급해도 된다. 신호를 받으면 2.5초 동안 3-dot 바운스 모션(`motion.span`, `y:[0,-4,0]` 반복, delay로 위상차)과 "입력 중" 텍스트를 상대 메시지 자리에 말풍선처럼 보여주고, 신호가 끊기면(추가 타이핑 없이 2.5초 경과) 자동으로 사라진다. 채팅창을 열고 닫을 때(컴포넌트 마운트/언마운트)마다 채널을 새로 구독/해제하므로, 이전 세션에서 발견됐던 "같은 table+filter 채널을 여러 컴포넌트가 동시에 구독해 무한 재연결"류 버그와는 구조적으로 무관함(postgres_changes가 아니라 순수 broadcast이고, 인스턴스당 한 번만 구독).

같은 컴포넌트에 메시지 수정·삭제를 추가함. 꾹 누르기(long-press, 480ms 타이머)는 기존 홀드-드래그(시각 표시) 제스처와 `onDown`/`onMove`/`onUp` 핸들러를 그대로 공유하되, 이동량이 6px를 넘으면(=드래그 의도로 판단) 타이머를 취소해 서로 간섭하지 않게 함. 내가 보낸 텍스트 메시지에서만 메뉴가 열리고, 본문(body)이 있을 때만 "수정" 버튼을 보여준다(이모티콘 메시지는 수정 대상에서 제외). 수정을 누르면 입력창에 원래 텍스트가 채워지고(`editingId` 상태), 다시 전송하면 새 `chat_edit_message` RPC(`supabase-setup.sql`)를 호출해 본문과 `edited=true`를 함께 갱신한다 — "chat update own" RLS 정책은 수신자(to_uid)의 읽음 처리 전용이라 발신자의 본문 수정에는 쓸 수 없어, 소유권(`from_uid = auth.uid()`)을 직접 검증하는 SECURITY DEFINER 함수로 별도 처리함. 수정된 메시지는 읽음 표시(옆에 붙는 방식)와 다르게, 말풍선 "위쪽"에 별도 줄로 "수정됨"이 표시된다. 삭제는 `puzzle_likes`/`puzzle_reposts`와 동일한 패턴 — 새 `"chat delete own"` RLS 정책(`using (auth.uid() = from_uid)`)과 `grant delete`를 추가해, `notifyDelete`처럼 REST DELETE를 직접 호출하되 이번엔 정책이 실제로 뒷받침한다.

퍼즐 공유 카드에도 같은 홀드-드래그(당기면 보낸 시각 표시)와 꾹 누르기 메뉴를 확장함. 다만 메뉴 구성은 텍스트 메시지와 달라 "수정" 대신 "전달"(`Send` 아이콘) 버튼을 두고, 그 옆에 내가 보낸 카드에서만 "삭제" 버튼을 보여준다. "전달"은 이미 있던 `PuzzleShareSheet`(퍼즐 탭에서 최초 공유할 때 쓰는 친구 선택 시트)를 그대로 재사용 — `puzzlePreviews`에 이미 캐싱돼 있는 퍼즐 데이터를 그 시트의 `puzzle` prop으로 그대로 넘기기만 하면 되므로 새 UI 없이 구현됨.

**버그 수정 (추가)**
퍼즐 풀이 화면·퍼즐 카드의 "공유" 버튼 텍스트가 좁은 flex 행에서 "공"/"유"로 두 줄 줄바꿈되던 문제를 고침(`whiteSpace:"nowrap"`, `flexShrink:0` 누락).

계정을 바꾸거나 로그아웃해도 직전 계정(혹은 게스트)의 퍼즐·프로필 데이터가 화면에 그대로 남아있던 문제를 고침 — `onAuth` 콜백이 각 필드를 "새 계정에 값이 있을 때만 덮어쓰기"(`if (pr.X) setX(...)`)로 처리해, 새 계정에 해당 필드가 비어 있으면 직전 상태가 그대로 남는 구조적 버그였다. 로그아웃(`logout()`)의 "없으면 기본값" 리셋 로직과 동일하게, `unlocked`/`puzzles`/`solved`/`likedPuzzles`/`repostedPuzzles`/`lineSolves`/`xp`/`coins`/`devBonusGranted`/`deletedPuzzles`/`archivedPuzzles`/`titles`/`currentTitle`/`ownedSkins`/`boardSkin`/`pieceSkin`/`dailyQuest`/`mainQuest`/`recentOpenings`를 전부 무조건 확정하도록 고침. 프로필(닉네임·chess.com 아이디·사진 등)도 직전 상태와 병합(`(p) => ({...p, ...})`)하던 것을 이 계정의 실제 값으로 완전히 교체하도록 바꿈. `logout()`에도 빠져 있던 `devBonusGranted`·프로필 세부 필드 초기화를 추가함.

**기능 — 배경음악·효과음**
사이트에 앤티크한 체스 분위기와 어울리는 잔잔한 배경음악을 추가함. 사용자가 직접 확보해 전달한 드뷔시 "달빛"(Clair de Lune, Suite bergamasque 3악장 — 작곡 자체는 퍼블릭 도메인) mp3를 `public/bgm/clair-de-lune.mp3`로 받아, 앱 최상단(모든 탭이 공유하는 루트 컴포넌트)에 `<audio loop preload="none">` 하나만 상시 마운트해 탭을 이동해도 재생이 끊기지 않게 함. 브라우저의 자동재생 정책상 사용자 제스처(클릭) 없이는 소리 있는 재생이 항상 막히므로 무리하게 자동재생을 시도하지 않고, 재생 상태(`bgmOn`)는 `<audio>`의 `play`/`pause` 이벤트를 그대로 구독해 실제 재생 여부와 항상 일치하도록 함. 켜기/끄기 선택은 `localStorage`(`occ_bgm_on`)에 기기별로 저장해, 다음 방문 때 자동재생을 한 번 더 시도함(이전에 재생을 허용받은 origin은 브라우저가 자동재생을 다시 허용해 줄 수 있음 — 실패해도 조용히 무시).

같은 맥락으로 짧은 효과음 두 종을 추가함 — 사용자가 전달한 버튼 클릭음(`public/sfx/click.mp3`)과 나무 재질 "탁" 소리(`public/sfx/move.mp3`), 그리고 기물이 실제로 잡힐 때 재생할 "퍽" 소리(`public/sfx/capture.mp3`, wooden thud)를 별도로 받아 구분함. 클릭음은 개별 버튼·카드마다 onClick을 일일이 손대는 대신, 사이트 전체가 이미 일관되게 쓰고 있는 `.press` 클래스(`index.css`)를 document 레벨 캡처 단계 클릭 리스너로 감지해 한 곳에서만 재생함(캡처 단계를 쓴 이유는 일부 하위 요소가 버블링 중 `stopPropagation`을 호출해도 그보다 먼저 실행돼 놓치지 않기 위함). 이동음은 LearnTab의 `go(san)`(수 블록 클릭·드래그·엔진 라인 클릭·프로모션 완료가 전부 이 함수 하나로 모임)와 PuzzleSolver의 `tryUserMove(from,to)` 두 central 함수에서 SAN 문자열에 "x"(포획, 앙파상 포함)가 있는지만으로 클릭/포획 소리를 갈라 재생함(`playMoveSfx`). 세 사운드 모두 `playSfx(name)`이 매번 `new Audio(src)`를 새로 만들어 재생해, 연속 클릭·연속 착수 시 이전 소리와 자연스럽게 겹쳐 들리게 함.

(v0.1.4 UI 정리) 사운드 관련 켜기/끄기·음량 조절 UI는 처음엔 헤더 아이콘 버튼으로 뒀다가, 사용자 요청에 따라 전부 제거하고 설정 탭의 새 "사운드" 카드 하나로 모음 — 배경음악·효과음 각각 토글 스위치(기존 개발자 모드 토글과 동일한 알약형 스위치 스타일 재사용)와 `<input type="range">` 음량 슬라이더(`accentColor: T.brass`로 테마 색 적용)를 둠. 음량은 `localStorage`(`occ_bgm_vol`/`occ_sfx_vol`)에 저장되고, 배경음악은 `<audio>` 엘리먼트에 직접 반영, 효과음은 재생 시점마다 저장된 값을 그대로 읽어 적용함.

### OpenChess v0.1.3 — 2026/7/17

**기능**
학습 탭 메인 보드의 평가치 바와 체스보드 사이에 엔진 상위 3줄(MultiPV-3, depth 15)을 표시함(`engine.evaluateMulti` 호출 추가, `pvUciToSans`/`pvContinuationText` 헬퍼로 UCI 수열을 이미 둔 수는 뺀 "지금 포지션부터의 다음 수"만 SAN으로 이어붙임). 각 줄이 보드 폭보다 길면 그 줄만 좌우로 스크롤되고, 줄을 클릭(스크롤 드래그와 구분하기 위해 pointerdown/up 좌표 차이를 확인)하면 그 줄의 첫 수가 보드에 그대로 두어짐. 평가치 바는 소수점 둘째 자리까지 표기하고, 백 유리 시 좌측(흰 구간)에 검은 텍스트, 흑 유리 시 우측(검은 구간)에 흰 텍스트로 자신이 놓인 구간과 항상 대비되도록 배치를 전환함(탐색 인디케이터도 겹치지 않게 반대편으로 이동). 흰색은 엔진 라인 평가치 배지(EvalBadge)와 동일한 순백(#FFFFFF)으로 통일.

상단 기보(SequenceBar)를 줄바꿈 대신 가로 스크롤로 바꾸고, 수가 늘어 화면에 다 안 담기면 자동으로 오른쪽(최신 수)으로 스크롤함(`scrollIntoView` 대신 이 바 자신의 `scrollLeft`만 직접 계산해, 조상 스크롤 컨테이너까지 함께 밀리지 않도록 함). 데스크톱에서 A/D 키 또는 </> 키가 보드 아래 이전/다음 버튼과 동일하게 동작하도록 키보드 단축키를 추가함(focus 모드·입력 필드·수식키 조합은 제외).

헤더 우상단 프로필 버튼을 눌러 여는 프로필 드롭다운 카드에도 설정 탭 "내 프로필"과 동일한 메인 퀘스트 진척도·푼 퍼즐 목록을 표시함.

`/about` 소개 페이지의 스크롤 애니메이션을 대폭 강화함 — 기존 일회성(`viewport:{once:true}`) 애니메이션을 반복 재생(`once:false`)으로 바꾸고, 체스판·기물 이미지를 활용한 데코보드(DecoBoard)와 실제 앱 화면 스크린샷을 페이지 전반에 추가함. 버전 업데이트 기록 페이지(2페이지 이후)도 텍스트를 좌우로 번갈아 배치하는 지그재그 레이아웃으로 재구성하고 체스보드·스크린샷을 강화함.

티어 여정 지도(TierJourneyMap)를 여러 방면으로 개선함 — 이미 지나온 구간의 연결선을 점선에서 노란색 실선(#F5C542)으로 바꾸고, 스크롤로 그 구간이 화면에 들어올 때마다(`whileInView`+`once:false`) 선이 그어지는 애니메이션이 반복 재생되도록 함. 이미 지나온 티어에는 초록 체크 배지를 반복 펄스 애니메이션과 함께 표시. 각 정거장도 스크롤로 화면에 들어올 때마다 작게·기울어진 채로 시작해 제자리로 펼쳐지는 애니메이션이 반복 재생됨. 잠금 아이콘은 제거하고, 티어 이미지는 상태(잠김/완료/현재)와 무관하게 항상 원본 색 그대로 표시함(기존 `muted` 흑백·채도 처리 제거). 아이언~그랜드마스터 7개 티어 각각의 느낌에 맞는 세로로 긴 배경 이미지를 추가함(WebP로 압축, 원본 색감 그대로 사용) — `TIER_STATIONS`를 티어별로 그룹핑해 그 구간의 세로 픽셀 범위를 구하고, 그 범위에 해당 티어 배경을 깔아 스크롤해서 지날 때만 자연스럽게 보이도록 함. 배경은 천천히 확대·이동하는 카메라 무브(켄 번즈)를 반복 재생하고, 인접한 티어 배경끼리는 위아래 CSS mask로 옅게 페이드시켜 자연스럽게 이어지도록 함. 헤더 티어 로고는 검색 버튼과의 여백을 늘리고 크기를 키움.

**UI**
퍼즐 탭 공유 버튼(퍼즐 카드·풀이 화면 모두)의 좌우 패딩을 늘리고, 배경을 옅은 브라스 틴트에서 어두운 색(`T.ebony2`)으로 바꿔 시인성을 높임.

헤더 티어 배지에서 XP 진행바·텍스트를 없애고 로고만 남김 — 자세한 진행도는 눌러서 여는 여정 지도에서 이미 볼 수 있어 헤더는 배지만으로 충분히 간결하게 유지.

기보 바·엔진 라인·공지 모달 등 스크롤 가능한 모든 영역에서 브라우저 기본 회색 스크롤바를 전역 CSS로 숨김(스크롤 동작 자체는 그대로 유지).

엔진 라인 각 줄의 평가치 배지 padding·최소폭·글자 크기와 줄 사이 여백을 훨씬 압축해 UI 밀도를 높임.

**버그 수정**
프로필의 "푼 퍼즐" 블록 UI가 왜곡(텍스트가 한 글자씩 줄바꿈)되던 문제를 수정함 — 카드 크기·비율을 퍼즐 탭 카드와 동일하게 맞추고, 표시 상한을 5개로 늘려 가로 스크롤로 볼 수 있게 함.

퍼즐 모식도·도감 오프닝 트리 모식도에서 콘텐츠가 없는 위치가 아닌데도 팬(드래그)이 멈추는 버그를 수정함 — 원인은 v0.1.2에서 추가한 "빈 공간 진입 방지" 로직(`schematicItemVisible`)이 블록의 완전 포함 여부만 판정해, 화면에 일부만 걸쳐 있어도 "안 보임"으로 잘못 판단했던 것 — 완전 포함 대신 AABB(경계 상자) 교차 판정으로 바꿔 해결.

퍼즐 풀이 중 컴퓨터의 응징 수 아이콘이 애니메이션 재생 도중 다른 아이콘으로 바뀌어 보이던(깜빡이는) 문제를 수정함 — `kind` 분류를 `setReply` 호출 이전에 미리 계산하도록 effect를 재구성. 오답을 두면 컴퓨터의 응징 수에 "최선의 수" 배지를 표시하고, 원위치로 되돌아가기까지의 대기 시간을 1000ms에서 1700ms로 늘려 응징 수를 충분히 볼 수 있게 함.

학습 탭의 수 블록(MoveTile)과 엔진 라인(EngineLines)이 같은 수를 서로 다른 검색(수 블록은 개별 빠른 검색 depth 15/movetime 700ms, 엔진 라인은 MultiPV-3 depth 15/movetime 3000ms)으로 평가해 값이 미세하게 갈리며 같은 수인데 서로 다르게 표시되던 문제를 수정함 — 겹치는 수는 항상 엔진 라인의 값을 그대로 물려받도록 동기화(집중 학습 화면도 같은 `live` 필드를 공유하므로 함께 해결돼, 결과적으로 학습 탭 전체가 하나의 엔진 결과로 통일됨). 같은 원리로 메인 평가치 바와 엔진 라인 1번째(최선의 수) 줄의 평가치도 항상 정확히 일치하도록 함.

실제 모바일(안드로이드 Chrome) 기기에서 학습 탭 UI 전체가 화면 폭보다 넓게 강제되어 보드 우측·기보 좌측이 잘려 보이는 심각한 왜곡 버그를 수정함. 원인은 세 곳에 겹쳐 있었다 — (1) `EngineLines`의 nowrap 텍스트 div에 `min-width:0`이 없어, flex 자식 기본값(`min-width:auto`) 때문에 `overflow-x:auto`가 사실상 무력화(스크롤되는 대신 그냥 커짐), (2) `SequenceBar`의 `scrollIntoView`가 이 바 자신이 아니라 조상 스크롤 컨테이너까지 함께 스크롤시키던 부작용, (3) `LearnTab` 카드를 감싸는 CSS Grid 아이템(`grid lg:grid-cols-2`의 직계 자식)에 `min-width:0`이 없어, grid 트랙 자체가 콘텐츠의 min-content 폭만큼 강제로 넓어지던 것(가장 근본적인 원인). 세 곳 모두 `minWidth:0`을 추가하고 `SequenceBar`는 로컬 `scrollLeft` 계산으로 전환해 해결 — 실제 버그 재현 스크린샷과 동일한 수순·뷰포트(393×851)로 재현 테스트해 `#root`의 오버플로가 122px에서 0px로 해소됨을 확인함.

일일 퀘스트(오프닝 플레이)의 클리어 조건 기보가, 큐레이션된 39개 오프닝 풀(`QUEST_OPENING_POOL`)에 없는 더 구체적인 하위 오프닝(집중학습·퍼즐 경로에서 5수 이상 진행해 `recentOpenings` 후보로 들어온 이름)이 뽑혔을 때 통째로 안 보이던 버그를 수정함 — `QUEST_OPENING_MOVES`에 없으면 오프닝 트리에서 `findOpeningPathByFuzzyName`으로 그 이름의 실제 경로를 찾아 대신 표기하도록 함(퀘스트 카드 리렌더가 1초 주기 갱신 카운트다운에 걸려 있어, 이 조회는 퀘스트 목록이 실제로 바뀔 때만 `useMemo`로 캐싱).

오프닝 플레이 퀘스트 문구 "{오프닝}로 chess.com에서 1국 플레이"를 "{오프닝}로 chess.com에서 게임 1회 플레이하기"로 다듬음.

### OpenChess v0.1.2 — 2026/7/16

**기능**
퍼즐에서 잘못된 수를 두면 곧장 원위치로 되돌리던 것을, 그 수를 뒀을 때 상대(컴퓨터)가 어떻게 응징하는지 엔진 최선 응수를 한 번 보여준 뒤(가능한 경우만) 응수→오답 순으로 두 단계 슬라이드 애니메이션과 함께 되돌리도록 함(PuzzleSolver의 `wrong`/`wrongReply`/`revertStage` 상태 머신). 엔진을 못 쓰는 상황(liveOn 꺼짐 등)은 기존처럼 오답만 바로 되돌림.

퍼즐 모식도·도감 오프닝 트리 모식도 모두 드래그·휠·확대축소로 블록이 하나도 없는 빈 공간까지 한없이 팬할 수 있던 것을 막음. 도감 트리는 나침반형(N/S/E/W) 레이아웃이라 팔 사이 네 귀퉁이가 항상 비어 있어, 단순 사각 바운딩 박스로 한계를 두면 그 빈 귀퉁이까지 허용해 버리는 문제가 있었음(직접 테스트하다 발견) — 사각 박스 근사 대신 블록 목록(items) 자체를 기준으로 "화면에 실제로 걸쳐 있는 블록이 있는지"를 직접 검사하고, 하나도 없으면 화면 중심에 가장 가까운 블록으로 스냅하는 `clampSchematicPan` 공용 함수를 추가해 두 모식도에 동일하게 적용함.

일일 퀘스트 4개(새 퍼즐 풀기·chess.com 활동 3종) 각각의 클리어 보상을 +10 XP에서 +10 OC 나이트 코인으로 변경(전체 완료 시 지급되는 50코인 보너스는 그대로 유지). `claimQuestXp`를 `claimQuestCoins`로 바꾸고 토스트도 coins 타입으로 통일.

사이트를 소개하는 별도 페이지(`/about`, `src/AboutPage.jsx`)를 신설함. `main.jsx`에서 경로를 보고 App(엔진 워커·Supabase 클라이언트 등 무거운 초기화 포함) 대신 이 가벼운 정적 컴포넌트를 렌더링하도록 분기(vercel.json의 SPA rewrite 덕분에 `/about` 직접 접속도 정상 동작). 퍼즐 풀이 화면(보드↔모식도)과 동일한 드래그 페이지 넘김 패턴으로 구성했고, 1페이지는 핵심 기능 소개(마스코트 삽화+말풍선, 좌우로 번갈아 배치되는 기능 카드, 실제 7단계 티어 이미지 쇼케이스), 2페이지부터는 CHANGELOG를 latest-first로 재구성한 `VERSION_HISTORY`(App.jsx의 CHANGELOG와는 별도 데이터 — 모달은 한 줄 요약, 이 페이지는 기능/UI/UX/성능/버그 수정/보안 카테고리로 나눠 조금 더 풀어 쓴 설명)를 보여줌. 버전마다 마스코트가 소개/마무리하는 말풍선과, 대표 기능을 이미지·애니메이션(티어 승급 연출 재현 데모, 티어 스트립, 아이콘 펄스 등)으로 보여주는 하이라이트를 추가하고 framer-motion으로 전 페이지에 진입/스크롤 애니메이션을 적용함. 공지 모달(`AnnouncementModal`)에 "업데이트 내역 자세히 보기" 링크(`/about?page=2`, 새 탭)를 추가해 연결함.

**버그 수정**
일일 퀘스트에서 "오프닝로 chess.com에서 1국 플레이"처럼 오프닝 이름이 비어 표시되던 버그를 수정함. 원인은 `questLabel`이 `q.opening`이 falsy일 때 "오프닝"으로 대체 표시하는데, `genDailyQuest`로 새로 만든 데이터는 항상 유효한 값을 넣지만 quests 배열 자체는 있으면서 그 안 opening 항목 값이 비거나 손상된 저장 데이터(18차 이전 구버전 `featured` 문자열 배열 구조는 `!dailyQuest.quests`로 이미 걸러졌지만, 그보다 미묘한 손상까지는 못 걸렀음)는 재생성 조건을 통과하지 못해 계속 남아 있었던 것 — 날짜 변경 시 재생성 조건에 quests 배열 각 항목의 유효성 검사(`dailyQuestQuestsValid`)를 추가해 다음 로드 때 자동 복구되도록 함.

퍼즐 진입/재시작 시 재생되는 컴퓨터의 첫 수(mistakeSan, 직전 실수 수)는 이미 지나간 수인데도 "계산 중" 점 애니메이션을 보여주거나 `isSacrifice` 추측값을 먼저 보여줬다 실제 엔진 판정으로 갈아끼우는 연출이 있어, 수 체계 아이콘이 중간에 눈에 띄게 바뀌어 보이던 버그를 수정함. 이 경우(`isSetupMistake`)는 추측·pending 없이 최종 판정이 나온 뒤 한 번만 아이콘을 표시하도록 `moveIcon` 계산 effect를 분리함.

**UI**
티어 로고 원(`TierLogoDisc`)의 배경을 기존 아이보리 그러데이션에서 사이트 전역 브라스 광택 톤(`T.brass`/`T.brassHi`)의 골드 그러데이션으로 바꾸고, 헤더 배지·퍼즐 탭 스트립·프로필 필·여정 지도 전반에서 로고·원 크기를 여러 차례에 걸쳐 축소함(특히 퍼즐 탭은 높이를 우선적으로 줄임). 퍼즐 탭 티어 스트립에서 다음 두 단계를 미리 보여주던 작은 배지·연결선(`NextCheckpointBadge`/`TierConnector`/`upcomingCheckpoints`)은 여정 지도와 중복이라 제거함.

공유받은 퍼즐을 그렇게 들어와서 풀면, 얻은 XP의 10%(반올림, 최소 1)가 공유해 준 친구에게 실시간으로 전달되도록 함. XP는 계정마다 클라이언트가 소유·저장하는 값이라(user_progress의 jsonb 블롭을 매번 전체 덮어쓰는 구조) 서버가 남의 XP를 직접 늘릴 수 없어, puzzle_share_reward RPC는 공유자에게 갈 chat_messages 시스템 메시지(보상 금액 포함)만 하나 남기고, 공유자 본인의 클라이언트가 이미 구독 중이던 채팅 실시간 갱신에서 그 메시지를 발견해 자기 XP에 더하고 화면 중앙에 애니메이션으로 보여준 뒤 읽음 처리함(오프라인이었다면 다음 접속 때 안읽은 채팅을 훑으며 소급 적용). 어떤 공유 메시지를 통해 왔는지를 서버에서 검증해 임의 id로 보상을 위조할 수 없게 막음.

퍼즐 리포스트 기능을 추가함(좋아요와 동일한 토글 방식). 리포스트한 퍼즐은 풀이수·좋아요와 무관하게 내 추천 퍼즐 후보 풀에 항상 섞여 들어가는데, 기존에 있던 "후보 풀에서 새로고침마다 6개만 결정적으로 다시 뽑아 보여주는" 메커니즘을 그대로 재사용해, 별도의 확률 로직 없이도 추천 퍼즐에 간헐적으로 나타났다 안 나타났다 하게 함.

퍼즐 카드·풀이 화면에 리포스트 수·공유 수를 좋아요 수 옆에 나란히 표시함.

설정 탭 "내 프로필"에서만 보이던 메인 퀘스트 진척도·푼 퍼즐 목록을, 유저 검색·친구 프로필(공개 프로필)에서도 볼 수 있게 함. profiles.pub jsonb에 이미 xp·solvedCount 등을 공개해 오던 것과 같은 방식으로 solvedNos(전역 공유 puzzles 테이블의 퍼즐 번호 배열 — 데이터 자체는 이미 공개돼 있으므로 번호만 실어도 카드 렌더에 충분)와 mainQuestSummary(챕터/문항 진행 요약 — 전체 챕터·문항 수는 CONTENT 기준이라 개인정보가 아니고 진행분만 개인)를 추가로 공개함. 공개 프로필에서 "푼 퍼즐" 카드를 누르면 그 자리에서 퍼즐 탭으로 이동해 직접 풀어볼 수 있음.

"푼 퍼즐" 목록은 내 프로필·공개 프로필 모두 앞쪽 3개만 미리 보여주고, 4개 이상이면 "더 보기" 버튼으로 전체를 스크롤 가능한 별도 창에서 확인하도록 함(SolvedPuzzlesBlock, 두 화면이 공용으로 씀). 공개 프로필 쪽은 처음엔 미리보기 3개 분량만 조회하고, "더 보기"를 실제로 눌렀을 때만 나머지 전체를 마저 불러온다 — 프로필을 열 때마다 전체를 조회하지 않도록 하는 절제. (버그 수정) 이 작업 전에는 공개 프로필의 "푼 퍼즐"에 60개 상한을 두었는데, solved가 Set이라 먼저 푼 순서대로 쌓이는 걸 그대로 slice(0,60)해 정작 가장 오래전에 푼 것들만 보이고 있었다(제목의 전체 개수와 실제 보이는 카드 수가 안 맞아도 안내조차 없었음) — 이번에 "더 보기"로 상한 자체를 없애면서 함께 해소됨. (버그 수정) "더 보기" 모달 안의 퍼즐 블록을 눌러도, renderCard가 호출부(내 프로필/공개 프로필)마다 자기 onClick을 직접 만들어 붙이던 구조라 onOpenPuzzle은 실행돼 뒤에서 탭·활성 퍼즐은 바뀌는데 모달 자체는 안 닫혀 화면이 그대로인 것처럼 보이는 문제가 있었다 — renderCard(p, onClick)로 바꿔 클릭 동작을 SolvedPuzzlesBlock이 직접 만들어 넘기게 하고, "더 보기" 모달 안에서는 그 onClick이 먼저 모달을 닫은 뒤 퍼즐을 열도록 해, 어디서 누르든 항상 그 퍼즐로 리디렉션되도록 함. **UI**
도감 탭 오프닝 트리에서, 점선으로 묶인 칭호(대표 오프닝) 영역의 이름 라벨이 그 영역의 바운딩 박스 모서리에 고정돼 있던 것을 그 오프닝의 최상위 수(실제로 그 영역이 시작되는 수) 바로 위로 옮김. 나침반 레이아웃은 팔의 방향(N/S/E/W)마다 "깊이"가 화면의 어느 쪽으로 뻗는지가 달라, 특히 1.e4 쪽(Italian Game·Ruy Lopez·Sicilian Defense 등 13개 대표 오프닝 중 8개가 여기 속함)은 뿌리가 영역의 위쪽이 아니라 아래쪽 끝에 있어, 라벨이 실제로는 그 오프닝과 무관한 가장 깊은 변화 근처에 붙어 있는 것처럼 보였다. 이미 계산해 두고 쓰지 않던 그룹별 rootX/rootY 좌표로 라벨을 앵커해, 나침반 방향과 무관하게 항상 "이름 텍스트 바로 밑에 최상위 수"가 오도록 함.

퍼즐 테마 3종의 카드 배경 패턴을 실제 수 체계 배지와 같은 색·기호 언어로 다시 디자인함. 기물 희생하기는 탁월한 수(brilliant) 배지와 같은 민트색 + "!!" 모티프(굵은 스템+사각 점 두 벌)를 그대로 가져옴. 우위 점하기는 부정확한 수(inaccuracy)와 같은 노란색으로, "?!"를 채움 없이 끊어진 점선 윤곽선과 주변 부스러기 획으로 갉아 먹힌 듯한 부식감을 내 "짓밟고 우위를 다진다"는 느낌을 표현함. 실수 응징하기는 블런더의 빨강→실수의 주황 그라데이션 위에 "?"·"??"를 올리고 그 위로 어긋난 균열선을 그어, 카드 배경색과 무관하게(색을 지우는 대신 어두운 균열선만 얹는 방식) 항상 "형체는 알아볼 수 있지만 심하게 파괴된" 인상을 주도록 함.

**버그 수정**
집중 학습에서 퍼즐이 자동 생성되는 방식 때문에, 실수(또는 부정확한 수)를 응징·전환하는 바로 그 수가 동시에 "탁월한 수"로도 분류되면 사실상 같은 포지션(setupSans+mistakeSan)에서 실수 응징하기(또는 우위 점하기) 퍼즐과 기물 희생하기 퍼즐이 각각 따로 생성돼, 겉보기엔 다른 퍼즐인데 내용은 거의 같은 것이 두 개 저장되던 문제를 해결함. 원인은 퍼즐 id에 테마 접두어("sac|"/"adv|")를 붙여 테마별로 별도 id 공간을 강제로 나눠 놓은 것 — 실제로는 실수 응징/우위 점하기는 "그 수 자신의 위치"가, 기물 희생하기는 "그 수 직전 위치"가 정체성인데 둘이 우연히 같은 포지션을 가리키는 경우가 흔했다. 이제 퍼즐 id는 테마와 무관하게 포지션+수로만 정해지고, `theme` 단일 값 대신 `themes` 배열로 바뀌어 한 포지션이 여러 테마에 해당하면 퍼즐 하나에 태그가 함께 붙는다(예: "실수 응징하기 · 기물 희생하기"). 필터 칩·카드·풀이 화면 모두 이 다중 태그를 반영하고, 이미 트리가 생성된 퍼즐에 새 테마가 뒤늦게 해당되면 재생성 없이 태그만 얹는다.

### OpenChess v0.0.6 — 2026/7/15

**성능**
도감 탭 오프닝 트리가 chess.com 대국이 많은 계정에서 심하게 렉이 걸리던 문제를 해결함. 트리 노드마다(최대 4000개) 잠금 여부를 매기려고 매번 전체 대국 배열을 훑는 O(노드 수 × 대국 수) 연산을 하고 있었던 것이 원인이었다 — 대국이 바뀔 때 한 번만 모든 수순 접두어를 Set에 담아 두고, 노드마다 O(1) 조회로 바꿈. 이와 별개로 chess.com 데이터를 감싸는 훅이 무관한 이유로 부모가 리렌더될 때마다 새 객체를 반환해 트리 전체가 불필요하게 다시 계산되던 것도 고침. 팬(드래그)·줌 중에도 노드 좌표 자체는 안 바뀌는데 스타일 계산이 매 프레임 다시 일어나던 부분은 memo 컴포넌트로 분리해 드래그 성능도 별도로 개선함.

도감 오프닝 트리(OpeningSchematic)를 조립하는 useMemo가 배경 로딩 중 약 220ms마다 전체를 다시 계산하는데, 그때마다 내부 노드마다 boardFromSans(path)로 루트부터 그 깊이만큼 수순을 처음부터 재생해 채택 등급을 매기고 있었음(O(노드 수 × 평균 깊이)). 트리를 훑는 재귀 함수가 어차피 부모→자식 순서의 DFS이므로, 부모가 이미 만든 보드를 그대로 물려받아 이번 수 하나만 한 번 더 적용하도록 바꿔 O(노드 수)로 줄임 — 대국이 많은 계정일수록, 트리가 깊고 넓을수록 체감 효과가 큼.

메인 체스보드에서 수를 둘 때마다 화면에 보이는 모든 후보 수(캡 없이 최대 수십 개)의 실시간 엔진 평가를 워커 하나로 한 번에 하나씩 순서대로 처리하고 있었음(수당 최대 700ms 상한이 있어도 총 대기 시간이 후보 수 개수에 정비례). 게임 리뷰(analyzeGame)가 이미 쓰던 "독립 워커 풀 + work-stealing" 패턴을 그대로 재사용해, 워커 여러 개(엔진 프로필별 2~4개)가 같은 목록에서 하나씩 꺼내 동시에 평가하도록 바꿈 — depth·movetime(정확도)은 손대지 않았으므로 정확도 손실 없이 벽시계 시간만 풀 크기만큼 줄어듦. 이 풀은 게임 리뷰와 달리 사용자가 수를 둘 때마다 반복 재사용되므로, 프로필이 바뀌지 않는 한 한 번 띄운 풀을 계속 재사용하도록 컴포넌트 생명주기에 걸쳐 캐싱함.

**기능**
도감 탭 오프닝 검색을 개선함 — 이전엔 상위 8개까지만 보여주고 순서도 사실상 임의였는데, 이제 검색어가 포함된 오프닝을 전부 보여주고 수순이 짧은(더 상위·유명한) 오프닝이 위로 오도록 정렬함. 검색 결과를 선택했을 때의 이동 애니메이션도 중심에서 목표까지 직선으로 가로지르던 것을, 나침반 중심에서 그 오프닝까지 실제로 이어지는 트리 선(ㄱ자 커넥터)을 그대로 따라가도록 바꿈.

레벨/XP 시스템을 전면 재편함. 기존 피보나치 곡선은 너무 가팔라(레벨 10에 누적 23,100 XP, 레벨 20엔 286만 XP) 사실상 레벨 10~13을 넘기지 못했는데, chess.com 퍼즐 티어나 리그 오브 레전드 같은 랭크 게임처럼 아이언·브론즈·실버·골드·다이아몬드·마스터·그랜드마스터 7단계 티어로 바꾸고, 각 티어를 다시 5단계 구간(1이 가장 높음)으로 나눔. 기물 테마(폰~킹 실루엣)는 그대로 유지하되 등급마다 고유한 색을 입힘. 헤더 티어 배지를 누르면 전체 여정 지도(구간마다 원 하나, 위로 갈수록 높은 등급)가 열리고, 퍼즐 탭 상단에도 지금 구간과 다음 두 단계를 미리 보여주는 스트립을 추가함.

유저 검색창을 열었을 때(아직 아무것도 입력하지 않은 기본 화면) 비어 있던 것을 "알 수도 있는 사람"(내 친구의 친구, 같이 아는 친구 수 순)과 "티어 리더보드"(XP 상위 플레이어) 두 갈래로 채움. 친구의 친구는 다른 사람의 friend_edges를 읽어야 하는데 RLS가 본인 관련 행만 읽도록 막아 둬 클라이언트에서 조합할 수 없어 서버 RPC(friend_suggestions)로 계산했고, 리더보드는 XP가 profiles.pub jsonb 안의 값이라 PostgREST 문자열 정렬로는 자릿수가 다른 숫자가 잘못 정렬될 수 있어 숫자로 캐스팅해 정렬하는 RPC(leaderboard_top)를 추가함.

개발자 모드(설정 탭)에 티어/경험치 테스트 패널을 추가함 — 임의 XP 증감량을 즉시 적용하거나 7개 티어 중 아무 곳으로나 곧장 점프할 수 있어, 실제로 퍼즐을 몇 주씩 풀지 않아도 승급 연출·티어별 색상·여정 지도를 바로 확인할 수 있음.

티어 여정·배지에 쓰던 직접 그린 로우폴리 SVG 기물 아이콘을 디자이너가 제작한 실제 티어 이미지(아이언 폰~그랜드마스터 홀로그램 킹)로 교체하고, 각 이미지의 실제 색을 뽑아 배지 테두리·글로우·진행바 색도 함께 맞춤(특히 마스터·그랜드마스터·다이아몬드가 기존 팔레트와 크게 달라짐). 세부 티어(1~5) 표기를 아라비아 숫자 대신 로마 숫자(I~V)로 바꿈 — 텍스트 라벨과 체크포인트 배지 양쪽 모두. 그랜드마스터 이후의 ★프레스티지 카운터는 1~5를 벗어나는 별도 무한 카운터라 그대로 아라비아 숫자로 둠.

하단 탭바의 퍼즐 탭 아이콘을 Google Fonts Material Symbols의 "extension"(퍼즐 조각 모양)으로 교체함. 외부 웹폰트 CDN 의존을 피하기 위해 퀘스트 탭 아이콘과 동일한 방식으로 공식 SVG 패스 데이터를 번들에 포함해 렌더링함.

**버그 수정**
오프닝·퍼즐 모식도에서 확대/축소 버튼·핀치가 pan은 그대로 두고 zoom만 바꿔, 화면 좌상단(콘텐츠 원점)을 기준으로 배율이 바뀌면서 팬으로 멀리 옮겨온 화면에서는 트리 전체가 화면 밖으로 사라진 것처럼 보이던 문제를 해결함(지점 기준 확대 공식 적용). 오프닝 트리·퍼즐 모식도의 기본 확대 배율도 다들 실제로 편하게 보던 배율(기존 75%)을 새 기준 100%로 재정의함.

설정 탭 내 프로필의 "오프닝별 승률" 목록에서, 영문 오프닝 이름과 통계를 한 줄에 양 끝 정렬로 배치하던 방식이 중첩이 깊어질수록(들여쓰기 누적) 이름 칸 너비가 몇 십 px까지 줄어들어 단어 하나하나가 줄바꿈되며 통계 배지와 겹쳐 보이던 문제를 해결함 — 깊이와 무관하게 항상 안전하도록 이름과 통계를 별도 줄로 분리함.

접속 시 뜨는 업데이트 공지 모달이 v0.0.5 이후로 새 버전 기록을 전혀 보여주지 못하던 문제를 해결함 — 코드 안의 버전 목록이 v0.0.4에서 갱신되지 않은 채 남아 있었다. 재발 방지로 APP_VERSION을 별도 상수로 관리하지 않고 CHANGELOG 배열의 첫 항목에서 그대로 파생하도록 바꿈 — 새 버전을 낼 때 CHANGELOG 배열에 항목 하나만 추가하면 되고, 버전 번호를 두 곳에 맞출 필요가 없어짐.

en passant 판정(epTarget)이 "직전 수의 도착 칸이 4/5랭크인 폰 수"이면 무조건 더블 푸시로 간주해, 폰이 한 칸씩 두 번(예: e2-e3, 그다음 턴에 e3-e4) 나눠 전진해도 앙파상을 허용하던 문제를 해결함 — 직전 수 바로 이전 보드에서 실제 출발 칸을 구해 진짜로 두 칸을 건너뛰었는지 검증하도록 함. 이와 별개로 boardToFen/sansToFen이 캐슬링 권리·앙파상 필드를 실제 수순과 무관하게 항상 "KQkq -"로 고정해 내보내던 문제도 해결함 — 킹/룩이 한 번 움직였다 제자리로 돌아와도 캐슬링 권리는 회복되지 않는데 엔진에는 여전히 합법이라고 알려 불법 캐슬링을 추천/수용할 수 있었고, 실제 앙파상 기회는 늘 "없음"으로 알려 엔진이 놓쳤음. 매 수의 실제 이동 정보(킹/룩 이동, 룩 시작 칸 포획, 진짜 더블 푸시 여부)로 캐슬링 권리·앙파상을 누적 계산해 반영하도록 함(기존 O(n²) 회피 최적화는 그대로 유지).

도감 탭에서 특정 수를 클릭한 직후 1~2초 동안 화면이 좌우로 심하게 흔들리고, 그 와중에 드래그하면 트리 전체가 사라지던(꽤 오래전부터 보고된) 문제를 근본 수정함. 원인은 pan/zoom 상태를 세 곳(centerOn이 시작하는 최대 900ms짜리 비행 애니메이션의 requestAnimationFrame 루프, selectedPath 재중앙 정렬용 150ms setInterval, 드래그/휠/확대버튼 같은 수동 조작)이 서로의 존재를 모른 채 동시에 덮어쓰고 있던 것 — 애니메이션이 매 프레임 부드럽게 보간하는 pan을 150ms interval이 "이미 다 도착한 것처럼" 곧장 스냅해버려 두 값이 150ms마다 서로를 덮어쓰며 튕겼고(흔들림의 정체), 그 상태에서 드래그를 시작해도 애니메이션이 멈추지 않아 다음 프레임이 드래그 결과를 계속 덮어써 화면이 엉뚱한 곳으로 튀었음(사라짐의 정체). 드래그·휠·확대 버튼 등 수동 조작이 시작되는 모든 지점에서 비행 애니메이션을 확실히 취소하고, 150ms interval은 애니메이션이 도는 동안 건너뛰도록 해 셋이 절대 동시에 pan/zoom을 다투지 않게 함.

도감 오프닝 검색 결과에서 두 가지를 고침 — (1) 부모 노드의 이름을 그대로 물려받아 같은 오프닝 이름이 서로 다른 수순 길이에 걸쳐 완전히 똑같은 문자열로 중복 등장하던 것을, 같은 이름 중 수순이 가장 짧은 노드 하나만 남기도록 함. (2) 검색어가 오프닝 이름 맨 앞에 오는 결과와 이름 중간 어딘가에 오는 결과가 뒤섞여 나와 찾으려던 오프닝이 관련 없어 보이는 결과들 사이에 묻히던 것을, 맨 앞에 오는 결과를 모두 먼저 보여준 뒤 중간에 오는 결과를 그 아래에 보여주도록 정렬을 바꿈.

학습 탭의 실시간 수 등급 판정(assignTiers)에 classifyMoveKind·analyzeGame과 동일한 "이미 승부가 기운 위치에서의 자포자기 희생은 탁월한 수로 안 쳐준다"는 완화 규칙이 빠져 있어, 같은 포지션이 게임 리뷰·퍼즐 채점과 다르게 학습 탭에서만 "탁월한 수"로 잘못 표시되던 문제를 해결함(퍼즐 생성 로직에도 같은 누락이 있어 함께 고침 — 이제 네 곳 모두 동일한 기준을 씀).

오프닝 이름 퍼지 매칭(findOpeningPathByFuzzyName, 일일 퀘스트에서 사용)이 "트리 이름이 검색어를 포함"과 "검색어가 트리 이름을 포함"을 한 조건으로 묶어 BFS 첫 매치를 반환해, 세부 바리에이션을 찾아도 그 접두어인 훨씬 상위(일반) 오프닝이 먼저 걸려 반환되던 문제를 해결함(퀘스트 오프닝 풀의 약 1/3에 영향). 트리 쪽이 더 구체적인 매치를 먼저 전부 찾고, 없을 때만 반대 방향으로 한 번 더 찾도록 두 단계로 분리함.

공지 모달 자동 표시 effect가 최초 로드 시점에만 판단해, 로그인(onAuth) 이후 서버에 저장된 dismissedAnnounceVersion 값이 바뀌어도 재평가되지 않던 문제를 해결함. 로그인 시 이 값을 "있으면만" 덮어써 계정이 한 번도 안 닫았으면 게스트 시절 값이 남던 문제도 함께 고침. 로그아웃해도 friendUids/puzzleSolvers/solverNames(친구 해결자 표시용 데이터)가 안 비워져 게스트 화면에 방금 로그아웃한 계정 친구들의 "N명이 풀었습니다" 배지가 남아 있던 문제, dismissedAnnounceVersion이 로그아웃 시 초기화되지 않아 게스트 로컬 저장소에 방금 로그아웃한 계정의 값이 새어 들어가던 문제도 함께 해결함.

알림 벨의 읽음/수락·거절/삭제가 전부 서버 요청 실패를 삼키고 낙관적 UI 업데이트를 되돌리지 않던 문제를 해결함 — 관련 서버 함수들이 성공 여부를 돌려주도록 바꾸고, 실패 시 로컬 오버레이를 지운 뒤 서버 상태와 다시 동기화하도록 함.

도감 오프닝 트리의 형제 수 상한(cap) 체크가 배치 내 모든 새 후보에 그 시점의 형제 수를 한 번만 읽어 적용해, 같은 배치에 비이론 수가 여럿 도착하면 상한을 넘겨 추가될 수 있던 문제를 해결함(장식적 문제, 데이터 손상은 아니었음).

학습 탭 실시간 워커 풀(위 성능 항목)에 생명주기 버그 3건도 함께 고침 — 엔진 프로필을 평가 도중 바꾸면 종료된 워커의 평가 Promise가 영영 안 끝나 그 후보 수의 평가가 멈춰 있던 문제, 워커 풀 부팅이 완전히 실패했을 때 수를 둘 때마다 매번 처음부터 재부팅을 시도해(URL당 최대 4초) 반복적으로 멈추던 문제, 컴포넌트가 언마운트된 뒤 뒤늦게 부팅된 워커가 정리되지 않아 Worker 스레드가 누수되던 문제.

**UI 개선**
내 프로필 카드에서 메인 퀘스트 진척도·푼 퍼즐 정보가 chess.com 대국 기록(분량이 길어 화면을 많이 차지함)보다 아래에 있어 한참 스크롤해야 보이던 것을, 퀘스트·퍼즐 정보를 먼저 보여주고 chess.com 데이터를 그 아래로 내리도록 순서를 바꿈.

티어 여정 지도에서 아직 안 온(잠긴) 구간이 전부 똑같은 회색으로 칠해져 각 티어 고유 색(브론즈 구릿빛, 골드 금빛, 다이아몬드 청록…)이 하나도 안 보이던 것을, 잠긴 상태에서도 그 티어 색을 낮은 채도·밝기로 남기도록 바꿔 스크롤할수록 앞으로 만날 색이 은은하게 미리 보이게 함. 퍼즐 탭 상단 티어 스트립의 구불구불한 지그재그 연결선도 좁은 가로 스트립 안에서는 오히려 어수선해 보인다는 이유로 직선으로 바꿈.

### OpenChess v0.0.5 — 2026/7/14

**보안**
퍼즐(`puzzles`) 테이블의 서버 쓰기 권한이 로그인 여부와 무관하게 사실상 전체 열려 있어, REST를 직접 호출하면 임의 퍼즐의 풀이수·좋아요 수를 원하는 값으로 덮어쓸 수 있었던 문제를 해결함. 두 카운터는 이제 원자적 증가를 보장하는 서버 함수(RPC)로만 바뀌도록 컬럼 단위 권한으로 좁혔고, 누구나(비로그인 포함) 새로 만난 퍼즐을 공유하는 기존 크라우드소싱 방식은 그대로 유지함.

로그인만 하면 다른 유저에게 임의 종류의 알림(칭호 획득, 레벨 업 등)을 위조해 보낼 수 있었던 문제를 해결함 — 알림 종류별로 실제 그 알림이 발생할 수 있는 상황(칭호·레벨 알림은 본인에게만, 친구 요청·수락 알림은 실제 친구 관계가 막 생겼을 때만)인지 서버에서 검증하도록 함.

채팅이 친구 관계와 무관하게 임의 유저에게 전송 가능했던 문제를 해결함 — 지금까지는 채팅 버튼이 친구 목록에만 노출될 뿐 서버가 이를 강제하지 않아, REST를 직접 호출하면 친구가 아닌 사람에게도 메시지를 보낼 수 있었다. 이제 서로 친구(수락됨) 상태일 때만 메시지가 저장되도록 서버에서도 검증함.

**성능**
알림(30초)·친구 요청 배지(30초)·채팅창(3초)·안 읽은 채팅 배지(15초)가 각자 독립적으로 반복 조회하던 방식을 실시간(Realtime) 구독으로 전환함 — 상대방의 행동이 즉시 반영되면서도 평소에는 불필요한 요청이 나가지 않음. 연결이 조용히 끊기는 경우를 대비해 1~2분 간격의 느슨한 안전망 재조회만 남겨둠.

페이지 배경의 기하학적 장식(선·도형)이 이 폴링들을 포함해 화면이 다시 그려질 때마다(자신은 내용이 전혀 바뀌지 않는데도) 매번 다시 계산되던 것을 고쳐, 최초 한 번만 그리도록 함.

### OpenChess v0.0.4 — 2026/7/13

**성능**
"게임 리뷰"(전체 기보 분석) 기능이 여전히 비정상적으로 느려지던 문제를 해결함. v0.0.2에서 분석 전용 병렬 워커 풀을 도입했지만, 그 풀의 첫 자리는 "유휴 상태일 것"이라는 가정 아래 앱 전역에서 공유하는 메인 엔진을 그대로 재사용하고 있었다 — 그런데 집중 학습의 실수 분석처럼 게임 리뷰와 무관하게 같은 엔진 큐에 계속 평가를 밀어넣는 경로가 있어, 이미 보드에 긴 기보나 많은 후보 수가 떠 있던 상태에서 새 게임을 리뷰하면 그 배경 작업 뒤에서 워커 한 자리가 계속 대기해 분석 전체가 느려지고 있었다. 이제 게임 리뷰는 메인 엔진 큐를 전혀 재사용하지 않고 완전히 독립된 전용 워커들로만 풀을 구성해, 다른 화면에서 무슨 작업이 진행 중이든 영향받지 않도록 함.

체스보드에서 수를 두거나 위치를 옮길 때마다 학습 탭 실시간 엔진 평가(평가치 바·수 추천 목록)가 체감상 느려진 문제도 함께 개선함. 이 실시간 평가는 movetime 없이 depth만 주고 있어, 복잡한 포지션에서는 목표 depth에 도달할 때까지 무제한으로 오래 걸릴 수 있었다 — 게임 리뷰·퍼즐 생성처럼 movetime 상한을 둬 depth·시간 중 먼저 도달하는 쪽에서 멈추게 했다. 또한 이 실시간 평가는 후보 수 목록이 채워질 때마다(비이론 수를 엔진으로 보충하며) 자기 자신이 다시 실행되는 구조인데, 재실행될 때마다 이미 평가해 둔 현재 포지션·후보 수까지 처음부터 다시 엔진에 물어보고 있었다(같은 포지션에 대한 완전히 중복된 질의). 포지션이 바뀌지 않는 한 이미 진행 중이거나 끝난 평가 결과를 재사용하도록 캐싱해, 같은 수를 둘러싸고 반복되던 중복 질의를 없앴다(측정상 특정 위치에서 완료까지 걸리는 엔진 요청 수가 약 절반으로, 총 소요 시간도 그만큼 줄어듦).

**버그 수정**
설정 탭의 chess.com 연동 오프닝 승률 트리에서, 모바일처럼 화면이 좁고 들여쓰기가 깊게 중첩된 오프닝일수록 이름이 최대 2줄로 제한된 뒤 말줄임(…)으로 잘려 전체 이름을 알아볼 수 없던 문제를 해결함. title 속성으로 전체 이름을 보여주려던 예전 대안은 모바일 터치 환경에서는 아예 작동하지 않았다 — 줄 수 제한을 없애 이름이 몇 줄이 되든 항상 끝까지 그대로 보이도록 함.

퍼즐(실수 응징하기·우위 점하기·기물 희생하기) 최초 생성이 유저의 "퍼즐 풀기" 클릭이 열어 둔 집중 학습 화면의 effect에 묶여 있어, 생성이 끝나기 전에 화면을 벗어나면(다른 탭으로 이동 등, 특히 로딩이 느린 모바일에서 자주 발생) 이미 다 돌아간 엔진 계산 결과가 그냥 버려지고 다음에 다시 처음부터 생성해야 했던 문제를 해결함. 생성 요청과 진행 상태를 앱 최상단(항상 마운트돼 있어 탭을 옮겨도 사라지지 않는 곳)으로 옮겨, 화면을 벗어나도 생성이 끝까지 이어지고 결과가 저장되도록 함. 아직 생성이 끝나지 않아 곧바로 퍼즐 탭으로 이동할 수 없는 경우에는 예전처럼 아무 반응 없는 버튼 대신 "퍼즐을 생성하는 중입니다" 문구와 진행 게이지를 보여주고, 완료되면 정상적인 "퍼즐 풀기" 버튼으로 바뀜.

퍼즐 모식도에서 실전에 자주 두어지지만 통과할 수 없는 "유혹 수"를 일부러 막힌 가지로 끼워 넣던 기능을 없앰 — 사용자가 그 가지를 실제로 시도해 보면 어디로도 이어지지 않는 리프가 그대로 모식도에 남아 "풀 수 없는 라인이 표시된다"는 혼란만 남겼다. 이제 통과 가능한 수만 분기에 남고, 이미 만들어진 퍼즐에 남아 있던 유혹 수 가지도 렌더링 단계에서 함께 걸러냄.

퍼즐 풀이 화면에서 컴퓨터가 둔 첫 수(직전 실수 수)의 수 체계 아이콘이 진입 시 잠깐(직전 수 재생 애니메이션 동안)만 보이다 애니메이션이 끝나자마자 사라지던 문제를 해결함 — 사용자가 첫 수를 두기 전까지는 계속 그 아이콘이 유지되도록 함.

퍼즐 라인을 몇 수 두어 보다가(아직 풀지 못한 채) "처음부터" 버튼을 누르면, 그 라인에서 이미 드러났던 수들이 모식도에서 도로 가려져(고스트로 되돌아가) 마치 진행 상황이 통째로 사라진 것처럼 보이던 문제를 해결함. 보드 진행 상태와 별개로 "이 세션에서 한 번이라도 실제로 두어 본 수"를 계속 누적해 두고, 모식도에 무엇을 보여줄지는 이 누적 기록(+실제로 해결한 라인) 기준으로만 판단하도록 해, 재시작해도 보드만 처음으로 돌아갈 뿐 이미 들여다본 모식도 내용은 그대로 남도록 함.

(참고) 퍼즐 탭 모식도의 기본 확대 배율은 이미 100%로 되어 있음을 확인함 — 코드를 점검한 결과 75% 등 다른 기본값으로 바뀐 지점을 찾지 못했다.

**기능**
접속 시 업데이트 소식을 알려주는 공지 창을 추가함. README 버전 기록을 바탕으로 개발 용어 없이 사용자 입장에서 쉬운 말로 다시 정리해 보여주고, 모든 버전의 기록을 한 창에서 스크롤로 볼 수 있음. "다시 보지 않기"를 체크한 채 닫으면 그 버전 번호가 계정(로그인 시 서버, 아니면 기기 로컬)에 저장되어 다음 접속부터 안 뜨다가, 새 버전이 나오면 다시 뜸. 체크하지 않고 닫으면 다음 접속 때 다시 보임.

사이트 전체 모식도(도감 오프닝 트리·퍼즐 모식도·개발자 트리 에디터)의 확대/축소 배율을 25%p 단위(25/50/75/100/125/150/175/200%)로만 고정함 — 버튼 클릭뿐 아니라 두 손가락 핀치나 마우스 휠 같은 연속적인 제스처로 나온 값도 항상 가장 가까운 단계로 스냅됨.

도감 탭에서 오프닝을 검색해 선택하면 예전엔 그 위치로 화면이 즉시 순간이동했는데, 지금은 원래 보고 있던 위치에서 목표 위치까지 파란 선을 그어 보여주고 그 선을 따라 매우 빠르게(0.22초) 화면이 이동하는 것처럼 보이는 애니메이션으로 바뀜.

**버그 수정**
도감 탭의 오프닝 트리가 배경에서 계속 더 깊이 채워지는데, 이 작업이 도감 탭 화면 자체에 묶여 있어 다른 탭에 갔다가 돌아오기만 해도(흔한 사용 패턴) 지금까지 쌓인 진행이 통째로 사라지고 처음부터 다시 시작되던 문제를 해결함 — 그래서 늘 얕은 수(약 6수)에서 멈춘 것처럼 보였다. 이 작업을 앱 최상단(항상 마운트돼 있는 곳)으로 옮겨, 어느 탭에 있든 계속 더 깊이(실제 이론 데이터가 있는 곳까지, 확인상 10수 이상) 채워지도록 함.

**기능**
퍼즐에 좋아요 기능을 추가함. 퍼즐 풀이 화면과 퍼즐 목록의 각 카드에 하트 아이콘과 좋아요 수가 함께 표시되며, 하트를 누르면 채워지고(좋아요) 다시 누르면 비워짐(취소). 좋아요 수는 같은 퍼즐을 푼 모든 유저에게 공통으로 합산되어 보이고, 로그인하지 않은 상태에서 하트를 누르면 로그인 창이 뜸.

**UI 개선**
메인 퀘스트 카드가 모바일에서 지나치게 길어 일일 퀘스트까지 한눈에 보이지 않던 문제를 해결함. 챕터를 좌우로 넘겨보던 방식은 넘기기 위해 모든 챕터가 한 줄에 나란히 있어야 했고, 그 여파로 지금 보는 챕터가 짧아도 항상 가장 긴 챕터의 높이에 맞춰 늘어나 있었다 — 이제 챕터를 아코디언(접기/펼치기) 방식으로 세로 나열해, 기본으로는 지금 진행 중인 챕터만 펼쳐지고 나머지(완료했거나 아직 잠긴 챕터)는 제목 줄만 보이도록 접혀 있어 전체 높이가 훨씬 짧아짐. 완료한 챕터는 제목 줄을 눌러 언제든 다시 펼쳐볼 수 있음. 또한 CHAPTER 2처럼 한 챕터 안에 하위 챕터가 여러 개(1.e4·1.d4·1.c4·1.Nf3 응수)인 경우, 예전엔 순서 없이 아무 응수나 먼저 풀 수 있었는데 이제 챕터끼리와 마찬가지로 앞 번호 응수부터 순서대로 클리어해야 다음 응수가 열림.

설정 탭의 내 프로필 카드에 메인 퀘스트 진척도(완료한 챕터 수·맞힌 문제 수, 진행률 막대)와 지금까지 푼 퍼즐 목록(카드 형태로 오프닝별 정렬, 좋아요 표시 포함)을 추가함. 푼 퍼즐 카드를 누르면 그 퍼즐 풀이 화면으로 바로 이동해 다시 볼 수 있음.

### OpenChess v0.0.3 — 2026/7/13

**기능**
도감 탭의 오프닝 수 트리를 나침반형(1.e4/1.d4/1.c4/1.Nf3이 각각 동서남북 네 방향으로 뻗어나가는) 레이아웃으로 전면 재설계함. 트리 정중앙에는 회로 칩 장식을 두어 네 갈래가 여기서 뻗어나간다는 느낌을 주고, 칭호 탭에 있는 13개 대표 오프닝(Italian Game, Ruy Lopez, Scotch Game, Sicilian Defense, Caro-Kann Defense, French Defense, Vienna Game, King's Gambit, Benoni Defense, Catalan Opening, Grünfeld Defense, London System, Queen's Gambit)만 점선 테두리로 하나의 영역으로 묶어 표시함. 영역 안의 더 구체적인 하위 바리에이션은 새 영역을 만들지 않고 그대로 상위 오프닝 영역에 포함되며, 영역 이름은 바깥 여백에 화살표와 장식체 글씨로 표기해 블록과 겹치지 않게 함.

**안정성**
트리가 배경에서 계속 자라는(비동기 로딩) 동안 이미 그려진 블록들이 계속 흔들리거나 위치가 튀던 문제를 근본적으로 해결함 — 형제 순서·leaf 좌표·나침반 팔의 기준점·자식이 있는(internal) 노드의 위치를 한 번 계산되면 다시 바뀌지 않도록 모두 캐싱하고, 위치가 바뀔 때 걸려 있던 짧은 슬라이드 애니메이션을 제거해(반복되는 미세 재조정이 애니메이션과 겹치며 화면이 계속 미끄러지는 것처럼 보였음) 순간 이동하도록 바꿈. 트리 로딩 초반 잠깐(약 3.2초) 재배치가 몰리는 구간은 화면을 가려 사용자가 그 과정을 보지 않게 하고, 화면을 드래그·확대할 때 렉이 걸리던 문제는 우선순위 계산용 Map을 pan/zoom이 바뀔 때마다 다시 만들던 것을 고쳐 해결함. 칭호 점선 영역이 배경 로딩으로 계속 커지다 일정 크기를 넘으면 사라지던 문제도 크기 상한을 없애 해결함.

**UI**
수 블록을 클릭하면 열리는 수 설명 카드가 모식도의 확대/축소 트랜스폼 안에 함께 있어, 축소하면 카드가 화면 밖으로 잘리고 확대하면 카드도 같이 커지던 문제를 해결함 — 카드를 트랜스폼 바깥(화면 좌표계)으로 분리해, 카드 자신의 크기는 항상 모식도 창 크기에 비례한 값으로 고정하고 앵커(수 블록)의 화면상 위치만 pan/zoom을 반영해 따라가도록 함.

### OpenChess v0.0.2 — 2026/7/12

**성능**
특정 대국의 "게임 리뷰"(전체 기보 분석) 기능이 기보가 길어질수록 끝없이 느려지다 멈춘 것처럼 보이던 문제를 해결함. 원인은 워커 하나가 모든 포지션을 순서대로 평가하던 구조라 총 분석 시간이 포지션 수에 정비례해 늘어난 것으로, depth·탐색 시간은 그대로 둔 채(정확도 손실 없이) 같은 엔진 프로필의 워커를 여러 개(Stockfish 18 Lite 4개, Stockfish 16 Full 2개) 띄워 포지션들을 나눠 동시에 계산하도록 바꿈. 이어서 교차 출처 격리(Cross-Origin-Opener/Embedder Policy) 헤더를 배포 설정(Vercel)과 로컬 개발 서버에 추가해 SharedArrayBuffer 기반 멀티스레드 Stockfish를 활성화, 실시간(집중 학습 등) 평가에 쓰는 메인 엔진이 활성 포지션 하나를 여러 CPU 코어로 동시에 탐색하도록 함(교차 출처 격리가 안 되는 구형 브라우저 등에서는 자동으로 기존 단일 스레드 빌드로 폴백). COEP는 require-corp 대신 credentialless를 적용해, CORP 헤더가 없는 외부 이미지(구글 프로필 사진 등) 로딩이 깨지는 부작용을 피함.

### OpenChess v0.0.1 — 2026/7/11

**UI**
모바일에서 상단 UI가 잘리는 문제를 해결하고 상단 UI를 최적화함. 학습 탭과 퍼즐 탭을 제외한 탭에서는 마스코트 이미지를 모두 제거해 UI를 정리하고, 로그인 창에는 마스코트 대신 OpenChess 로고를 표시함. 프로필과 집중 학습 모드에 나오는 모든 대국에 타임 컨트롤(래피드/블리츠/불릿)을 표기하고, 레이팅 증감폭은 게임 결과 뒤 소괄호로 표기함. 마스터 대국이 표시되지 않던 문제를 해결하고(불러오는 중에는 "마스터 대국 기록 탐색 중..."으로 표기), 학습 탭 메인 체스보드 크기를 키우고, 수 체계 아이콘이 계산되기 전에는 3-dot 타이핑 인디케이터 스타일의 바운스 애니메이션을 보여주도록 함. 평가치에 따라 제안 화살표의 두께·투명도가 달라지던 UI가 적용되지 않던 문제를 고치고, 기본 보드 스킨 테두리에 금색 광택 효과를 적용해 사이트 전체 미니 체스보드에도 반영, 기물을 하단 블록 기준으로 정렬하도록 좌표 정렬 문제를 해결함. 도감 탭에서는 수 블록 주변에 오프닝 이름을 표시하고 채택률 대신 책 아이콘을 좌상단에 배치, 퍼즐 탭에서는 퍼즐 블록이 하단 탭에 가리던 문제와 모바일에서 추천 퍼즐이 안 뜨던 문제를 해결하고 모식도 크기를 75%에서 100%로, 2페이지에도 미니 체스보드를 추가해 블록 클릭 시 애니메이션 재생이 되도록 함. 상점 탭은 보유 코인 UI를 축소해 우상단에 배치하고 기물 스킨은 "흑 나이트" 한 기물만, 보드 스킨은 8×8 이미지로 보여주도록 하고, 설정 탭은 내 프로필에 칭호를 이름 위에, 레이팅 변동·정확도를 집중 학습 모드와 통일해 표기함. 친구 기능은 채팅 버튼을 아이콘으로 바꾸고, 친구 삭제 버튼은 프로필 클릭 후 우상단에만 노출되도록 함.

**UX**
집중 학습 모드에서 자주 둔 다음 수를 클릭하면 그 수의 집중 학습 모드로 바로 이동하고, 다른 수의 집중 학습 모드를 거쳐 나갈 때는 체스보드에 해당 수순이 표시되도록 개선함. 도감 탭의 오프닝 수 트리는 첫 위치를 1.e4로 정렬하고 하위 라인을 계속 생성하도록 하며, 수 설명 창이 X 버튼으로 안 닫히던 문제와 오프닝 이름 클릭 시 집중 학습 모드로 이동하지 않던 문제를 해결함. 검색 기능은 버튼을 누르지 않아도 입력값에 따라 실시간으로 프로필을 띄우도록 하고, 프로필 클릭 시 하단 정보 확인이 막히던 스크롤 문제를 해결함. chess.com 연동 시 데이터가 많은 계정의 로딩이 느리던 문제를 보완하기 위해 정보를 순차적으로 불러오는 즉시 표기하고, 최근 대국 기록도 최신순으로 불러오도록 함.

**시스템**
framer-motion 의존성을 추가해 로그인/회원가입 모달에 배경 페이드 및 스프링 인 패널 애니메이션을 적용했고, Claude Code용 ui-ux-pro-max 디자인 스킬을 벤더링해 이후 작업에서 디자인 스타일·색상·타이포그래피·UX 가이드라인을 참고할 수 있게 함.

### OpenChess v0.0.0 (Beta) — 2026/7/10

**기능**
기초적인 웹사이트의 구조와 틀은 모두 갖추었고, 웹사이트의 핵심 기능인 학습 탭과 퍼즐 탭은 거의 완성 단계에 도달, 퀘스트 탭과 도감 탭은 전반적인 수정이 필요하고, 상점 탭 및 설정 탭은 미완성 상태, 그 외 검색 기능, 친구 기능, 채팅 기능, 알림 기능 역시 조금 발전이 필요함. 향후 베타테스팅을 고려하여 개발자 기능의 편의성을 조금 개선할 것.

**UI**
학습 탭을 제외하면 심각한 상태, 여전히 필요없는 텍스트가 너무 많고, 비율이 왜곡되거나 레이아웃이 부자연스러운 부분이 꽤 있으며, 모바일 비율에서는 심각한 불편함을 느낄 정도로 레이아웃이 컷오프되는 현상도 발생함.

**UX**
UI에 비해 비교적 양호한 편이기는 하나 여전히 만족스러울 정도로 부드럽고 깔끔한 느낌은 아님, 특히 웹사이트 전반에 사용되는 체스보드의 착수 UX와 기물 움직임 애니메이션을 가장 먼저 다듬어두면 앞으로 유용할 것으로 보임.

**시스템**
개발 언어는 JavaScript, 전반적인 개발 과정은 Claude Code의 Sonnet 5.0, Opus 4.8, Fable 5로 진행됨, 디자인은 Flaticon, Google Fonts를 활용하였고, 일부 이미지는 직접 디자인함. openchess.kr 도메인과 함께 각 탭을 하나의 경로(/learn, /book, /puzzle, /quest, /store, /setting)로 지정하여 구분하였고, 1차적인 취약점 검사를 통해 일반적인 보안 기준을 충족함. Github Repository에서 개발한 PR을 Merge하면 Vercel에서 자동으로 deploy하는 방식, Supabase를 통해 서버 데이터를 저장하고, OpenChess 자체 계정과 Google OAuth 서비스를 통한 Google 계정을 연동할 수 있게 함.
